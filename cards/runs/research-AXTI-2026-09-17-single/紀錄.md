**runner 立場(不是裁決):** 同一方向、更連貫的論證、成本約五分之一。B 的優勢在「一個人從頭到尾持有論點」——它能把第一季與第二季逐字稿並讀出「目標上調節奏」,六角色版沒有任何一層做到。B 的弱點:沒有獨立反方——A 的反方抓出「1.3 億口徑歧義」與「少數股東重複扣除」這類錯,B 沒有人核它;它的樂觀情境用了 50% 毛利率與 11% 折現率同時成立,是否過寬無人挑戰。**這正是 W2 覆核入口要接的位置:B + 一次針對性覆核,而不是 A 的七次派工。** 一個樣本不決定形態優劣;第二股(INTU)按計劃再比。

## 三、留下的問題

- 服務層 `publish_research` 未把臨時價格陣列傳給發布器畫圖(bars=None),頁面只有衍生數字;W2 補「取臨時日線 → 畫圖 → 不保存」。
- 補查請求登記仍由 runner 重建 packet;應成為 `save_research` 內的一步。
- `EvidenceRegistry` 只出 0.2.0 記錄,runner 改標 0.3.0(與 v03 fixture 同法);登記器應加 contract_version 參數。
- 隔離仍靠指令(Claude Code Agent 工具);W2 的 API 執行路徑才在工具層落實。
- 兩份研究的分歧「能見度兩季 vs 多年」值得下一輪覆核先答,它決定基準內在價值是 23 還是 28。
