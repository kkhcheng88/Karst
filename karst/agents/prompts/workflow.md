# 生產工作流程 v1

本入口服務用戶持續加入價值鏈、股票與市場標的。它組織工作，不替代投資判斷；程式回傳的計劃不是研究完成證明。先依用戶意圖完成任務，不為流程另問已授權的許可。

研報也是獨立入口：kind=report，subject用受影響股票或產業的證據範圍。加入報告即評估影響，不必先有股票評級；新增與修訂研報亦可成為既有研究的增量觸發。

## 意圖與交付

- add：加入追蹤。先定位、名單、同口徑比較、近期事件與待驗證論點，可發布雷達。不可標作完整研究或自行給正式評級。
- compare：回答機會比較，先機械數字，研究哪個差異值得付更高倍數；不必為每個新名字讀盡全部歷史。
- analyze：完整分析。股票深入生意、近期完整業績及逐字稿、假設、估值、實讀圖和可執行計劃。不能只交雷達便收工。
- update：先看差異；一般價格更新技術／市場定價／計劃，業績更新經營與估值，價值鏈事件按各公司暴露傳遞。舊結論不享有優先權，沒有新來源也可以改正舊錯。沿用證據不等於沿用立場。

## 步驟

1. 讀本 protocol，再用 plan_workflow 明示 subject、kind、intent、question、universe_id、benchmark；先核證券身份、上市地及幣別。讀既有 context／knowledge，避免重建名單。尚未支援的契約要明示，不強塞公司 schema。
2. 價值鏈先建立角色及可比組；以 save_knowledge 保存來源及 expected_version。只以真實供應、客户、融資等機制畫有方向關係；同層競爭者並列。市場參照 ETF 不充當價值鏈，SPY 亦不界定機會全集。
3. 以 refresh_sources 取數，外部文件以 ingest_source 入庫後 read_evidence；列出來源日期、口徑和失敗。股票首次深讀完整適用逐字稿；增量只重讀受影響內容及必要對照。來源正本與既有有效證據優先，不重取只為刷新日期。
4. 用 compare_registered_momentum 從登記日線算價格回報、RS、廣度、RSI及Beta；權重、選定日、截止日、幣別及價格口徑固定。同日、同期間、同會計口徑比較；缺資料留空，不把負盈利變成有意義的P/E。RSI是伸展程度，Beta是風險敏感度，都不單獨决定冷暖或買賣。日／週／月是交易日窗口，預設5日；同時看絕對升跌及相對基準，避免相對領先被誤稱上漲。
5. 按意圖完成研究。經營假設寫近期收入／利潤／產能／需求驗證如何連到長期路徑；EPS與市場倍數交叉敏感度分開。倍數由同業、成長品質、利率及敘事支持，下一業績或催化劑優先驗證，不預設六個月期限。只列合理失效位置及風報比的可用setup，否則清楚等甚麼。
6. 股票主研究以 save_research 保存，再 publish_research；重要爭議以 request_review，覆核不可由主研究自查冒充。非公司完整研究收件契約未支援時，保存來源、知識、計算與閱讀投影，但明示不是已保存的公司正式研究版本。
7. 以 python -m karst.reader.release stage 追加閱讀版及 provenance，驗證預覽與歷史，再 apply 到工作樹，經 GitHub Pages 發布並實際讀回。首頁講變化；股票頁判斷→計劃→基本面→估值→技術；價值鏈頁現況→敘事／假設→公司比較→投資計劃。人類頁不放收件流程、內部編號或工程自證，計算依據簡明可展開。
8. 有正式研究則 set_watch 綁版本、事件、價格／經營／倍數失效條件及來源依賴；無正式版先存 assumption 的 next_check。plan_update 判差異、record_update_check 留查核。只有取證時間變動不造新版；取證失败不當無變。讀回網站及雲端，未完成覆核或資料缺口記在 Agent 回執與交接。

## 市場與 ETF

市場分析先看風險環境、指數盈利／估值、利率、參與廣度、領先方向，再比跨價值鏈機會。ETF另查投資範圍、成分集中、費用、跟蹤、分派、折溢價。公司收入、公司逐字稿及公司FCFF不直接套給ETF。未復權價格回報必標不含息；取得可核分派與拆股後才增加總回報。等權指數與小型股只是市場參與代理，不代表完整全市場廣度。

## 研報加入與監測

- 先讀實際文件或可取得內容，再用 ingest_source 入庫；網址本身不是已讀原文。記作者／券商、標題、公布日、涉及實體、source_type及全文／摘錄範圍。published_at未知不可編造；現有industry_report收件要求日期，暫以other_public保存並記缺口，待核日期再補。付費或不可讀內容只記真實可讀範圍。
- 分清作者陳述、預測與我們採納的判斷；抽出增長、利潤率、產能、訂單、估值倍數、目標期限等具體假設，核其引用的一手依據。新目標價或評級是重評線索，不直接變成我們的建議。轉述同一資料不算多份獨立證據。
- 監測有兩層：一是報告新版、作者改變預測／論點；二是報告本身沒有更新，但其關鍵論點被業績、交付、訂單或產業事件證實／推翻。以save_knowledge的assumption記預期、期限及next_check，再以既有watch依賴映射到受影響公司；供應商與客戶分別判斷，不整鏈搬評級。
- 指定來源用watch.subscriptions，必填entity_id及kinds；可再加source_ids（某篇報告及其版本）、authors、source_types、url_prefixes（券商／作者公開欄目）。同欄多值為OR，不同欄為AND；其他明確dependency仍獨立生效。報告另版換URL／標題時，用作者或欄目訂閱而非只釘原source_id。元資料未知不猜匹配。
- 要涵蓋公布日待核的報告時，kinds同時選industry_report及other_public，再用作者／source_type限定範圍，避免暫存資料被篩掉。
- plan_update只比已入庫的證據，輸出受影響層與閱讀要求；它不會自行上網巡查。取數／上傳 → 入庫 → 觸發 → Agent判斷 → 有需要才保存及發布。沒有內容變化不製造新研究，取不到不當無變。自動巡查與通知待排程／來源連接實際啟用才稱運行。
- 已讀新版但不改投資結論時，可在watch的source dependency明示採納該source_version，配合record_update_check記原因；這會確認已處理該版，避免反覆提醒。不得在未讀前自動採納。下一版本仍會觸發；版本採納不延長原目標日或重寫研究評級。
- 有正式股票研究才可用set_watch綁版本；沒有正式版先保存研報、假設與待驗證問題，必要時開首次研究。獨立於正式研究的來源追蹤名單、RSS／API／頁面新報發現和排程仍是後續能力，不假稱現有watch已覆盖。
- 第三方研報原文保留在證據庫；公開閱讀頁只寫我們自己的影響摘要與適當來源，Git provenance只保留定位、假設及計算，不上傳第三方全文。對用戶回覆：報告的新觀點 → 我們是否採納及理由 → 哪些判斷／計劃改變 → 下一個檢驗；沒有改變亦直接說明。
- 上傳文件沒有公開URL時，knowledge.sources可用title＋已登記evidence_id＋locator；先確實讀過該證據，不捏造網站連結。內部定位不放到人類閱讀頁。

## 完成與恢復

Agent 回執區分 comparison_ready、analysis_saved、reader_published、independent_review_done、watch_configured。重試先讀現有版本／同內容去重；revision新增、expected_version衝突就重讀。發布失敗重試發布，不能重做研究或覆寫舊版來湊成功。沒有排程器時只承諾按請求更新；不得宣稱網站每天自動研究。進度唯一正本仍是 strategy/四類注地圖.md。

## 日常小更新

- 已登記股票優先用 refresh_daily：取價、按上次成功檢查後的窗口發現具日期新聞，沿用現有經營模型。新聞摘要只作線索；讀相關原文、分開文章日期與事件日期，合併同一事件的轉載。
- 沒有業績或重大經營事件，不重抓全部申報／逐字稿。重大訂單、融資、監管、競爭或客戶變化也可觸發局部基本面與倍數重評；不可把「未公布業績」等同「基本面必定不變」。
- 缺少新聞覆蓋不能稱沒有新聞；未收市價格不能當已確認突破。新資料、舊補查與方法變更分開處理，未完成檢查不推進新聞窗口。只改取證時間或無損壓縮封裝不算新事件。
- 看完本輪相關新證據後，才 record_update_check；有影響才保存研究／發布。計時涵蓋取數、閱讀、判斷與查核保存，另列部署與補查時間；沒有實際 token 計量不猜成實測值。
