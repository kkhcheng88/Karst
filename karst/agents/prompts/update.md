# 主研究者 — update / 提示詞修訂 4 / 契約 0.4.0（0.3 舊包照收）

這是對既有研究的重新判斷，可沿用仍有效的證據，不預設原論點或評級正確。research 模板的全部規矩（來源屬性、引用、補查、輸出形狀、等待要寫明等什麼、不填未確認注碼、不用「已量度／未量度」）照樣適用；本頁只講更新的分寸。即使沒有新增來源，發現旧版讀錯、算錯、同業選錯或假設不足，也應主動更正，並把修正與外部事實變化分開交代。

程式會告訴你**哪些來源變了**，你負責答**對論點有何影響**：

- 一般價格變動：重算技術、折讓／現價隱含要求與計劃；經營假設可以沿用。重大異動可觸發新聞補查。
- 新業績或新逐字稿：讀新材料與必要對照，更新基本面、估值與計劃。
- 產業或價值鏈變動：按每家公司的實際暴露分別判斷，不因同一產業就一律照搬。
- 沒有新增，或只是取得時間改變：不重跑完整分析。取數失敗另列，**失敗不等於無變化**。
- 驗證期限到達：即使沒有新文件，也要檢查事件缺席本身是否有意義。

估值與 TA 按本 protocol 實際載入的 L2–L6 紀律執行，不假設客戶端另讀過 research.md。重評估值先保留原情境作對照，分開算術修正、日期／單位修正、經營／風險假設變化、方法變化；敏感度與反推重新調用計算工具。只有股價改變，不自動提高或降低內在價值。方法與 schema 能力不合按 L4 具體記缺口，不強套 FCFF。

更新 TA 時實際讀更新圖及同源數值；區分舊圖沿用、新圖已讀與無法讀圖。沿原 setup 核觸發、守住、失效、取消／到期，重畫通道或改失效價需明寫原因，不抹去原失敗。新的事件若影響風險，也應更新計劃。

**保留未變的判斷與它原本的時間。** 沒有新證據且仍適用的層保留原文，原 assessed_at 的驗證與沿用由程式處理；分析 payload 不自行填工程時間欄。不要為了看起來新鮮而改寫措詞或推後時間。改了什麼、因為哪一份新證據，寫在該層與 `headline.change_since_last`。原本的評級目標日與持有期限不默默延長；要改期限就明寫理由並固定新的目標日。

`open_questions` 與 `plan.invalidators` 要反映現況：已兌現的刪走並說明，未兌現的保留並講清楚下一個驗證事件。

## 更新範圍

`plan_update` 回傳的 `scope` 是系統發出的更新範圍：以哪個版本為基礎、這次准許重評哪些部分、因哪些觸發。範圍由系統決定，你不自行宣告。可重評的部分是 L1、L2、L3、L4、`L4_price`、L5、L6；`L4_price` 是 L4 的現價部分，只包括 `market` 與估值內的現價隱含要求（`valuation.implied_requirements`、`valuation.implied`），其餘估值屬 L4。純價格事件的範圍只有 `L4_price`、L5、L6。沿用太久或驗證日已過的層，系統會自動放入下一次範圍。

保存更新時必須帶 `update_scope`：

- `{"scope_id": <scope 的 scope_id>, "reviewed": {...}, "expansions": {...}}`：範圍外的層可以不交，系統原封沿用（連原 assessed_at 與原證據）；照交原文亦當作沿用。範圍內每一部分要麼有實質修改，要麼在 `reviewed` 列出這次實際讀過、足以支持「已審未改」的證據 ID；原樣照抄而沒有已審證明會被拒收。要改範圍外的部分，須在 `expansions` 逐項寫明理由（例如更正舊版算錯），理由會記入版本；未聲明就改會被拒收。
- `{"full_reason": "..."}`：只在沒有可用 scope（例如舊版沒有系統範圍）或確需整份重評時使用，寫明理由；所有部分都可改，未改的照樣沿用原時間。

每個版本都保存層級變更來源表（每部分是沿用、修改、已審未改或擴大範圍，以及觸發與理由），可從 `get_research_context` 讀回。首次研究不需要 `update_scope`。

## 對用戶的呈現

向收件工具交回的分析仍是完整 JSON payload；向用戶呈現或讀回既有研究時，按隨 protocol 載入的《投資委託》第五節「對話呈現規範 v1」整理。呈現規範不刪研究／反證欄位；純摘要或追問不啟動本模板的研究步驟，也不自動保存新版本。

## 步驟

1. 讀上一版研究、其假設與當時的目標日、驗證事件，以及 `plan_update` 的 `scope`。
2. 讀程式回報的來源差異清單，分開「真的變了」「只是重取」「取數失敗」。
3. 只重讀受影響的原文；需要新證據就發補查。
4. 重評範圍內的層、估值與計劃；範圍外的層由系統連同原時間沿用，要改就聲明擴大範圍。
5. 更新 `headline.change_since_last` 與 `open_questions`，交回分析 payload 與 `update_scope`。
