## 工作內容

檢視視窗自此對任一日期段都算得出八項指標,不止全期。KARST-032 發現:指標層一給起訖日期就拋錯,因為視窗只截成交記錄、不承接視窗開始前已開的倉,配對來回時遇到「賣出但手上無貨」。應以視窗起始日的持倉為期初存貨(按當日估值作成本),再配對;淨值由起始日重設基準(與 window_stats 一致)。範圍只是指標層的視窗處理,不改指標定義、不改運行。

## 結果

· 2026-08-28 08:18 KARST-039-window2

檢視視窗現在承接視窗之前已開的倉,任一日期段都算得出八項指標。

**做法**:視窗開始之前最後一個交易日收工時手上有什麼,就按**那一日的收市價**入帳做期初存貨(opening inventory),再與視窗之內的成交先入先出配對。取前一日收價、不取視窗第一日收價,是因為 `window_stats` 把淨值由視窗第一日的收市值重設為 100:用前一日收價,視窗第一日本身那些成交仍然算在這一段之內,而且全期視窗完全不受影響(全期的第一日之前沒有前一日,期初存貨必然是空,走的就是未有這一層之前那條路)。代價是承接回來那一注的成本與淨值基準之間差住第一日那一日的走勢,數目細但不是零,已在 `karst/metrics/inventory.py` 開頭寫明。

**口徑兩句**:來回類三項(勝率、盈虧比、平均持倉日數)只計這一段之內平了倉的來回,段尾仍然揸住的倉不入——它未有結果;淨值類幾項(累計回報、年化、最大回撤、Sortino)自然含未實現,因為逐日淨值本身已經把未平倉按當日收價估足值,段尾那一日的估值已經在裡面。另外兩條:承接回來那批貨不計入成交金額(換手只數這一段真正落過的單),入場費用亦不計(那筆費用在上一段已經付過,算落這一段等於收兩次)。

**示例** —— `run-728a01087531258f`(趨勢波段)取 2023-01-01 起的視窗,即 2023-01-03 ~ 2026-08-26、915 個交易日,承接 4 注期初存貨:

| 指標 | 數 |
|---|---|
| 累計回報 | 81.66% |
| 年化回報 | 17.89% |
| 最大回撤 | -18.14% |
| 勝率 | 48.19% |
| 盈虧比 | 1.96 |
| 年化超額(QQQ) | -14.21% |
| 年化超額(SPY) | -4.87% |
| Sortino | 1.44 |
| 平均持倉日數 | 49.55 個交易日 |
| 換手 | 3.91 轉/年 |
| 已平倉來回 | 83 個 |

同一段在改動之前是直接拋 `ContractViolation`:「2023-01-27 賣出實體 5 但手上沒有貨」。

**驗收條件逐項**

- [x] **任一起訖日期算得出八項指標,不拋錯** —— 同一次運行掃 80 個起始日,全部算得出、零拋錯;另試五段任意起訖(包括只給開始日、只給結束日)亦全部通過。測試 `test_any_window_computes_eight_metrics_with_positions_carried_in`:該段之內只得兩張賣單、買入全部落在視窗之前,不承接就必拋 `ContractViolation`(測試明文釘住這一點),承接之後八項全部有數。
- [x] **全期視窗的八項數字與現行結果逐位相同** —— `run-728a01087531258f` 全期十一個數(八項連同已平倉來回數)與改動前逐位相同,期初存貨 0 注;明明白白給足全期起訖,答案與留空一模一樣。測試 `test_the_whole_period_numbers_do_not_move`,另核對「不餵期初存貨」與「未有這個參數之前」是同一個結果。
- [x] **期初存貨處置寫明,與 window_stats 的基準重設一致** —— 估值日就是 `window_stats` 重設基準那一日的前一格,測試逐格核對兩者相鄰;每一注的股數取估值日收工的持倉,成本取同一日、同一個快照的收市價(規格 8.4、D-026 第 4 條:換一個快照整條歷史會變,兩邊就不可比);承接回來那注的持倉日數由視窗第一日起數,視窗之前揸過幾耐是上一段的事。處置寫在 `karst/metrics/inventory.py` 開頭、`round_trips` 的 `RoundTrip` 說明與 `run_metrics` 的說明三處。測試 `test_opening_inventory_is_valued_the_day_before_the_rebase_day`。
- [x] **網頁殼用同一接口即可顯示檢視視窗的八項** —— 同一個 `run_metrics(runs, run_id, risk_free_rate=…, start=…, end=…, snapshot_root=…)`,未加新接口、未改網頁殼;網頁殼那份 JSON 用它砌得出來(用真實運行實試過,即上表那一段)。測試 `test_the_same_call_serves_the_web_shell`。

**留了一道明擋**:持倉的實體在快照裡查不到收市價,當場拋 `NotFound` 並講明是哪一隻、截至哪一日,**不當成本是零**——填 0 會令那一注的來回賺足全副身家,比「算不出」更壞(與因子值缺失不填 0 同制,D-021 第 4 條)。
