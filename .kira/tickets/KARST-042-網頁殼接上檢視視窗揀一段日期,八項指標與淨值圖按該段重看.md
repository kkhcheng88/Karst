## 工作內容

網頁殼自此可以在同一次運行上揀一段日期重看:淨值由該段起始日重設基準、八項指標按該段重算(含承接視窗前已開的倉)、蠟燭圖與買賣標記聚焦該段;是重看不是重跑,運行編號不變。KARST-039 已把指標層接口做通,KARST-032 留言指出網頁殼仍只叫全期。範圍是網頁殼與薄 REST 層接上起訖日期,畫面照原型第十版「檢視視窗」元件,不重開畫面決定。

## 驗收條件

- [x] 頁面可揀起訖日期,八項指標與淨值圖隨之按該段重算,運行編號不變
- [x] 薄 REST 層以起訖日期取數,頁面內無自行計算指標
- [x] 全期(不揀日期)的顯示與現行逐位相同
- [x] 視窗前已有持倉的運行(run-728a01087531258f 取 2023-01-01 起)顯示得出八項指標不報錯

## 結果

· 2026-08-28 08:34 網頁殼接上檢視視窗。運行詳情頁的淨值圖面板頭之下多了一列

指標、淨值線與兩條基準線、蠟燭圖與買賣標記全部按該段重出;運行編號、參數、快照一個
字不變——是重看不是重跑。網址記住那一段(`?run=…&start=…`),重新整理或者把連結
傳開,看到的仍然是同一段。

分工:頁面只負責把兩個日子交出去,一個指標都不算。薄 REST 層兩個端點

## 留言

KARST-042-webwindow(2026-08-28):design-system 3.7 寫的是「一個自訂日期輸入」,
但本票驗收條件要求「可揀起訖日期」,所以自訂那格做了兩個(起、訖),同一個 `.sp-date`
樣式、同一列。這不是重開畫面決定,只是把已核准那件元件補足到驗收要求的形狀;3.7 那句
要不要跟住改,留待畫面正本的持有人裁決。

KARST-042-webwindow(2026-08-28):蠟燭圖的「聚焦該段」做法——揀了日期,K 線、標記與
逐筆交易一律收窄到該段;不揀日期則一整條歷史照舊。原因是快照的價格歷史往往長過運行
本身,全期時若照視窗切,現行畫面反而會短一截,撞正「全期逐位不變」那一條。

KARST-042-webwindow(2026-08-28):沒有缺接口。`run_metrics(start=, end=)`、
`window_stats`、`opening_inventory` 三個接口足夠,網頁殼一層都不用繞路。
