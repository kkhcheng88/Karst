## 工作內容

完成之後,用戶可以憑一份規格核准工作台 v1 的骨架,而實作票可以按它拆而不需再討論結構。規格要答:(一)三層各存什麼、不存什麼——證據層(檔案,內容定址,只准追加,版本可取回,不入 git)、研究卡層(Markdown 加結構化卡頭;公司卡內多個論點各有穩定編號、產業卡按鏈位、市場卡按主題;git 為歷史)、索引與狀態層(SQLite;可重建的索引與必須持久保存的執行狀態分開;發布日誌只准追加,索引可由它與卡頭重建,不靠走 git 歷史);(二)編號與目錄:公司用 CIK、鏈位編號、主題編號、假設編號帶版本、證據編號=內容指紋加來源加取得時間;(三)兩種關係:證據依賴(這版卡的哪一層用了哪份證據、哪個假設版本)與更新訂閱(這家公司有新申報/逐字稿/價格、這條鏈有新假設、這個主題有新資料時,重評哪些層);新文件入庫時由程式加便宜模型標記涉及的公司、主題、鏈位,令從未被引用的文件也能觸發,並能發現新的關聯;(四)發布協定:模型只出結構化修改提案,程式驗編號、引用、欄位後生成 Markdown;發布時核對所用的卡版本,過期即重整合或重跑;保存結果與輸入版本 → 提交 → 更新索引與任務三步可恢復,中斷後對帳補完;單一寫入程序只約束發布階段,分析可並行;(五)更新路由按受影響範圍不按固定層:價格變動除技術與計劃外亦重算估值折讓、反向估值隱含要求與組合曝險;異常價格觸發補查;催化劑到期、等待事件未發生、假設到覆核期,無新文件亦觸發;(六)與現有資產的接口:data/sec、data/prices、DefeatBeta、富途 MCP、Longbridge 各自作為證據來源怎樣入庫;84 宗回歸集怎樣接成管線改動的回歸測試;①估值計算器與價值鏈人手表由 tag 還原後放在哪一層;(七)三項驗收的具體測試設計;(八)不做的事與改換時點(PostgreSQL、WeKnora、多寫入程序)。寫成 strategy/specs/投研工作台-v1-規格書.md,附一頁給用戶批的摘要。

## 驗收條件

- [ ] 規格書答齊(一)至(八),每一項有一段可獨立核對的定義;反例:任何一項只有方向沒有定義(例如「按需要設計」),即不合格
- [ ] 三項驗收各有具體測試設計:新文件從未被任何卡引用仍能觸發正確的卡與層;發布中途失敗重啟後任務不漏、不重複發布;任何已發布投資計劃可取回它所用的卡版本、假設版本與證據確切內容;反例:驗收只寫目標不寫怎樣測,即不合格
