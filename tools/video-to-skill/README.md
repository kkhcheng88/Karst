## 一句講完

輸入一個 KOL 交易員的名字,跑通:

```
搜尋 → 候選片單(用戶剔選,不代選) → 字幕抽取 → 代理抽取性質 → 筆記落 research/
```

腳本負責前三步(搜尋、字幕),第四步(代理抽取)由本檔下方的提示模板驅動,
第五步是人手(或代理)寫一份筆記存 `research/`。

## 步驟

### 1. 搜尋 → 候選清單

```bash
PYTHONUTF8=1 python tools/video-to-skill/search.py "<KOL 名字>"
```

輸出到 `research/_candidates/<名字>/candidates.csv` 與 `candidates.md`。
預設用三條查詢後綴(「交易 訪談」「交易系統」「投資 心法」)各取 30 筆、去重。
可用 `--queries` 自訂、`--limit` 調每條查詢筆數、`--out-dir` 改輸出位置。

**這一步不下載任何內容,只列名單。**

### 2. 用戶剔選(不代選)

打開 `candidates.md`,在「選」欄用 `x` 剔選要抽字幕的影片。篩選準則:

- **優先:訪談類、系統/方法論披露類**——標題含「訪問」「系統」「心法」「揭秘」
  「訪談」一類,傾向披露具體規則,是 Video to Skill 真正要的材料。
- **跳過:純行情評論類**——「Live 直播」「XX 股點睇」「今日大市」一類節目多數
  是即市評論,鮮少披露可機械化的規則,亦通常沒有逐字稿(直播多數只有
  live_chat,不算字幕,見下方限制 2)。
- 標題重複出現同一系列(例:同一訪談拆成多集)、或明顯是剪輯自其他節目的
  二次轉載,留一條有代表性的即可,不必逐條抽。
- 不用一次過剔到盡:抽取是迭代過程(參考 Eric 筆記分「第一輪」「第二輪」),
  先抽 3–5 條質素高的,看抽取結果再決定要不要補。

剔選完,把揀中的 video id 存做一份清單檔(每行一個 id,可直接複製
`candidates.md` 那一欄的值),交給下一步。

### 3. 字幕抽取

```bash
PYTHONUTF8=1 python tools/video-to-skill/captions.py --ids-file 已剔選.txt --out-dir research/_captions/<名字>
```

或直接列 id:

```bash
PYTHONUTF8=1 python tools/video-to-skill/captions.py --ids Ubv1YW_5uPI jOhjFLl0TRs --out-dir research/_captions/<名字>
```

每條片依序:呼叫 yt-dlp 抓字幕(人手字幕優先,無人手字幕退而求其次用自動
字幕)→ 有抓到就轉純文字存 `<out-dir>/<video_id>.txt`;抓不到就記入
`<out-dir>/skipped.md`,不中止其餘影片。

原始 json3 字幕檔存 `<out-dir>/_raw/`,不必理會,純文字檔才是下一步的輸入。

### 4. 代理抽取

把 `<out-dir>/*.txt` 交給代理(這個 repo 用 Claude Code 對話或子 agent),
用下方「抽取提示模板」跑一次,產出結構跟 Eric 筆記、Minervini 筆記同款。

### 5. 筆記落檔

存到 `research/YYYY-MM-DD-<對象>-video-to-skill.md`。若後續發現需要多輪
抽取(某個缺口未補齊),沿用 Eric 筆記「第二輪」的做法,同一份筆記加新節,
不要開新檔案分裂正本。

## 三個已知限制與處理方式

1. **429 限速。** yt-dlp 本身在 `captions.py` 內已加 `--sleep-requests 2`;
   腳本另外在每條片之間加 `--sleep`(預設 2 秒,可調)。片單大時建議分批跑
   (例如一次 5–8 條),撞到限速就停一停再續,不用一次過掃完整個頻道。
2. **好多片無字幕。** 只有 live_chat(直播聊天紀錄)不算字幕。`captions.py`
   抓不到 `.json3` 檔的一律記入 `skipped.md`,不當錯誤中止其餘影片。跳過的
   片若判斷內容重要,可考慮語音轉文字補抽(本管線目前未內建,是否要做由
   用戶決定,參考 Eric 筆記第九節「建議向用戶補充的資料」的處理方式)。
3. **自動字幕的數字要回片核對。** 自動辨識質素一般,人名、機構名、股票
   代號、指標名稱、具體數字都可能有錯字或漏字。代理抽取時,任何要入引擎
   的具體數字(百分比門檻、天數、比賽成績一類),筆記裡都要標明是否已回
   原片核對過;業績聲稱(勝率、回報率、比賽名次一類)一律標「自述未核實」,
   不當作既定事實。

## 代理抽取的提示模板

沿用 Eric 筆記(`research/2026-08-26-trader-eric-video-to-skill.md`)的章節
形態,把下面這段交給代理,附上 `<out-dir>/*.txt` 的內容:

```
你是幫 Karst(量化交易平台)做 Video to Skill 材料抽取的代理。

輸入:一位 KOL 交易員 <對象名> 的訪談/系統披露片段逐字稿(自動字幕轉純
文字,質素一般,人名/數字可能有誤)。

邊界(嚴格遵守,對應 Karst 決策 D-008):
- 只抽「性質」,不評價策略優劣,不代用戶判斷應否採用。
- 不虛構逐字稿沒提到的細節;還原不確定的地方要逐項標明「還原未核實」。
- 業績聲稱(勝率、回報率、比賽名次一類)一律標「自述,未核實」,不當既定事實。

產出一份 Markdown 筆記,章節結構如下(可按材料實際內容增減,但順序與
「可形式化評估」一節必須保留):

一、交易對象、市場與落注單位
二、時間框架與換倉節奏
三、訊號來源(技術面/基本面/消息面,按材料實際分類)
四、進場、出場、風控——盡量還原成條文
五、他自述的方法論結構(如有)
六、業績聲稱(一律「自述,未核實」)
七、可形式化評估——本節是給 Karst 引擎用的核心產出,分三級:
    A. 完全可形式化——可直接寫成引擎規則或量化因子(逐條列表,附形式化
       形態與出處)
    B. 部分可形式化——要補一層定義或額外數據才落得了引擎(逐條列表,
       明確寫「缺什麼」)
    C. 難以形式化——主觀裁量,寫明為什麼形式化不了
    D. 對 Karst 的結論(2–4 點,講清楚這套系統的可形式化程度、最容易先
       落地的部分、瓶頸在哪)
八、字幕質素影響到的地方(引用前必須回看原片的清單)
九、建議向用戶補充的資料

每一條規則後面用「(出處:片X)」標明來自哪一段材料,方便日後回片核對。
```

|---|---|---|
| `search.py` | KOL 名字 | `research/_candidates/<名字>/candidates.{csv,md}` |

| `json3_to_text.py` | 單一 json3 字幕檔(也可當模組被 `captions.py` 呼叫) | 純文字檔 |
