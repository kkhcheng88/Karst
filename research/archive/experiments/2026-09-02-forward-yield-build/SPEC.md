## 一、要砌的兩條線

| 欄 | 定義 | 起點 |
|---|---|---|
| `ey_lag` | 後顧盈利收益率 = Σ 成員(已公布滾動十二個月盈利) ÷ Σ 成員市值 | 1998-12 |
| `ey_fwd` | 前瞻盈利收益率 = Σ 成員(未來四季預估盈利) ÷ Σ 成員市值 | 2002 起(受數據深度所限) |

兩條都是**指數式聚合**(總和比總和),與現有 `pe_lag` 正本同一套算法:蝕錢成員照計入分子,**不剔走**(D-089 已判剔走蝕錢成員那種算法不可用)。

`ey_lag` 與現有 `pe_lag` 的關係:`ey_lag = 1 / pe_lag`,但 `pe_lag` 在板塊總盈利 ≤ 0 那幾格會變成未定義(現有正本寫 0.0 或 NaN),而 `ey_lag` 直接由盈利÷市值算,**負盈利期照樣有值、序列不斷線**。這正是本票要改口徑的原因。

## 二、成員名單與權重——與現有月度正本逐格一致

不另起爐灶。直接重用 `experiments/2026-09-02-multiples-oracle-scan/data/constituent_panel.parquet`,即 KARST-133 那條管線的逐股月度面板:

- 成分:`karst/data/universes/sp500_historical.csv`,帶 `joined_on` / `left_on` 生效期,無倖存者偏差;
- 板塊分類:defeatbeta `stock_profile.sector` → 九隻 SPDR(XLK/XLF/XLV/XLY/XLP/XLI/XLE/XLB/XLU);今日分類回溯 = 分類前視,沿用原管線的已知限制;
- 市值:月底收市價 × as-of 在外股數(兩者皆已按拆股還原至今日基準);
- 後顧盈利:defeatbeta `stock_tailing_eps`,取 `report_date + 60 日 ≤ 月底` 的最近一季(現實公布滯後);
- 板塊最少成員數 8(不足判缺);MKT 層為全部成分合成一條,不設下限。

**權重即市值權重**,由聚合式本身隱含,不另設權重欄。

## 三、前瞻分子的砌法

來源:`yfinance.Ticker.get_earnings_dates(limit=100)`(KARST-125 定案,裁決 D-093)。每列 = 一次業績公布,帶公布日期、該季 `EPS Estimate`(公布前夕分析員共識)、`Reported EPS`。

逐成員逐月:

1. 在月底 `m`,取該公司**公布日嚴格晚於 m** 的預估列,按公布日排序取最早四筆;
2. 四筆都要有非空 `EPS Estimate`,且第四筆公布日在 `m + 450 日` 之內,否則該成員該月**判為無前瞻**;
3. 成員前瞻盈利 `earn_fwd_est = (四季預估 EPS 之和) × 該月在外股數`;
4. 板塊 `ey_fwd = Σ earn_fwd_est ÷ Σ mcap`,分母只計**同一批有前瞻的成員**(分子分母同一批,不容分母用全體、分子用部分)。

### 3.1 同時砌一條低洩漏對照線 `ey_fwd1`

**這一節是本規格最重要的一條,寫在跑數之前。**

yfinance 儲的預估值,是該季**公布前一刻**的共識,公布後定格(KARST-125 第 4.1 節)。所以在月底 `m` 取「未來第四季」的預估,那個數其實是 `m` 之後大約十至十二個月才成形的共識——**它含有 m 當時未知的修訂資訊**。這與 D-108 判死的「重錨近似混入動量」同一個病:用未來才知道的東西砌一條看似前瞻的線,訊號會憑空變靚。

處理方法是**同時砌兩條,一併交付,讓 KARST-137 兩條都跑**:

| 欄 | 分子 | 前視洩漏上限 |
|---|---|---|
| `ey_fwd` | 未來四季預估之和(真 NTM 口徑) | 約 12 個月 |
| `ey_fwd1` | 未來第一季預估 × 4(年化) | 約 3 個月(下一次公布日距 m 的距離) |

若兩條給出的判詞不同,以 `ey_fwd1` 為準——它洩漏少。這一句寫在跑數之前,不是看完結果才揀。

### 3.2 精度篩

拆過重股的公司,舊季度每股預估被還原到今日基準後**只剩兩位小數**(KARST-125 第 4.1 節:NVDA 2017 年那格今日儲存為 `0.03`)。0.005 的進位誤差落在 0.03 上是 ±17%,做不了分母。

判法:某季預估 `|est| < 0.20`(即半步進位誤差 > 2.5%)標記為**低精度**。交付三樣:

- `ey_fwd`:全體(不篩),作正本;
- `ey_fwd_hp`:剔走任何一季落在低精度的成員之後重算;
- `lowprec_mcap_share`:低精度成員佔該板塊該月市值比重。

若 `ey_fwd` 與 `ey_fwd_hp` 分歧大,報告要明講,並建議 KARST-137 用 `ey_fwd_hp`。

## 四、覆蓋率的定義

`cov_fwd` = 有前瞻預估的成員市值 ÷ 該板塊該月全體成員市值。這是本票的**主覆蓋指標**(不是成員隻數比,因為市值權重才是真正影響聚合值的東西)。

**收貨門檻(跑數前寫死)**:2002 年起,九隻板塊逐年 `cov_fwd` 中位數 ≥ 50% 才算砌得成序列。長期低於一半即照票面第 3 條處理——136 如實收檔、137 舉手不跑。

## 五、輸出欄位

`sector_yields.csv`,一列 = 一個 `(month_end, series)`:

```
month_end, series, n_members, total_mcap,
ey_lag, n_lag,
ey_fwd, n_fwd, cov_fwd,
ey_fwd1, n_fwd1, cov_fwd1,
ey_fwd_hp, n_fwd_hp, lowprec_mcap_share
```

`series` ∈ {MKT, XLB, XLE, XLF, XLI, XLK, XLP, XLU, XLV, XLY}。月底頻,1998-12 至 2026-08。

## 六、快取與 API 紀律

- 逐隻公司抓一次 `get_earnings_dates`,結果落 `cache/earnings_dates/<SYMBOL>.parquet`,**已存在即跳過**,不重複打 API;
- 分批 + 指數退避重試,批間停頓,避免限速;
- 抓不到的公司(除牌、無預估)寫入 `cache/fetch_log.csv` 記明原因,計入覆蓋率統計;
- `cache/` 全部不入 git(大檔紀律)。
