# 失敗運行核對(D-034,KARST-077)

> 跑法(倉根目錄):
> ```
> set PYTHONUTF8=1
> set PYTHONPATH=.
> python experiments/2026-08-29-failed-runs/audit_failed_runs.py
> ```
> 只讀本機定義庫與運行序列,不寫庫、不改任何登記;結果落 `summary.json`。
> 判準本身用的是 `karst.web.data.is_failed_run`——與 `/api/overview`、
> `/api/strategy/runs` 兩個端點同一份正本,這裡不另抄一套演算法,只是把
> 它套在庫內每一條正式運行上,獨立核對一次。

## 一句話

**本機定義庫目前一共 9 條「判得出」的正式運行,8 條是失敗運行(年化回報同時
低於 SPY 與 QQQ 買入持有)——趨勢波段 7 條全部失敗,因子混合(ETF 版)唯一
一條可判的運行也失敗,只有因子輪動(ETF 版)那一條不是失敗運行。**

趨勢波段是「全部正式運行都失敗」的策略,正好用來驗 D-040 補的那個邊界情況
(策略總覽該行仍要列出、成績留空、對基準一格顯示「N 條運行全部失敗」)。

## 判準

一次正式運行的年化回報(全期,`window_stats` 口徑),若**同時**低於 SPY 與
QQQ 買入持有在同一快照、同一段期間的年化回報,即為失敗運行。任一基準當期
算不出年化回報(缺值),就不判——運行照列,不歸入失敗。門檻本身沒有可調
參數:「兩者皆低於」是判準,不是掃描格。

序列缺失的運行(KARST-057;逐日序列不在磁碟上)一律排除在外,不判、不計
入分母——與運行清單、策略詳情頁同一條規矩:登記照舊在案,清單不列。

## 結果

| 策略 | 可判運行 | 序列缺失(不判) | 失敗運行 |
|---|---:|---:|---:|
| 趨勢波段 | 7 | 1 | 7(全部) |
| 因子混合(ETF 版) | 1 | 1 | 1(全部) |
| 因子輪動(ETF 版) | 1 | 0 | 0 |
| **合計** | **9** | **2** | **8** |

逐條運行的年化回報與對應的 SPY/QQQ 年化回報見 `summary.json`。三套策略當中:

- **趨勢波段**:7 條可判運行年化回報介乎 10.8%–13.7%,同期 SPY 13.9%、
  QQQ 19.0%(兩次快照的 QQQ 年化在小數點後幾位有差異,屬不同快照期間的
  正常現象,不影響判定)——全部 7 條都同時低於兩者。
- **因子混合(ETF 版)**:唯一一條可判運行年化 13.2%,同期 SPY 13.9%、
  QQQ 19.0%,同時低於兩者,判定失敗。
- **因子輪動(ETF 版)**:唯一一條運行年化 19.2%,高於同期 SPY 13.9%,
  不同時低於兩者,不是失敗運行。

## 對照畫面

- `/api/overview`:因子輪動(ETF 版)照常顯示成績;趨勢波段、因子混合
  (ETF 版)兩套策略仍列一行(名稱、型別照顯示),成績欄留空,「對基準」
  一格顯示「N 條運行全部失敗(年化回報同時低於 SPY 與 QQQ 買入持有)。」
- `/api/strategy?id=<趨勢波段>` 的歷次運行表:7 條運行一條都不列,顯示同一句
  「7 條運行全部失敗……」,不是「此策略未有正式運行」那句。
- `/api/strategy/runs`:預設回應不含這 8 條失敗運行(`failedCount` 各自報
  7 與 1);帶 `?all=1` 仍取得完整名單,供核對用。
- 掃描格運行(`SWEEP_RUN` 來源)不受本票影響,`/sweep` 頁一切照舊。

以上四點對應 `tests/test_web_overview.py`、`tests/test_web_strategy.py` 的
自動測試斷言,兩者皆已針對本機真實庫跑通(見票內留言)。
