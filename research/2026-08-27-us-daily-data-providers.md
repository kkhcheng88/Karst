# 美股日線行情來源調研(查證日:2026-08-27)

## 範圍與方法

要答的問題:回測平台要接一個美股日線行情來源(全市場股票+ETF,含已退市股票以避免存活者偏差,含除權除息調整與停牌資料),供 vectorbt 引擎使用。查證方式:先查 `research/` 下 KARST-001、KARST-002、KARST-010 三份報告有沒有提過數據供應商(見下段),然後逐一網上查證十個候選連 tradingview-screener 套件的現況。**本報告只交事實,不做取捨建議**——供應商選型涉及月費預算與商業條款,由用戶裁決。

### 既有報告查重結果

三份既有報告都沒有正面答過「用什麼數據源」這條問題:

- **KARST-001**(回測框架調研)只提到引擎(vectorbt/PyBroker)本身有沒有處理存活者偏差、企業行動調整的機制,沒有評估外部數據供應商。
- **KARST-002**(因子基建調研)完全沒有提數據供應商,焦點是因子的定義形態與時點紀律。
- **KARST-010**(指定倉調研)裡提到的數據源都是綁死 A 股/幣圈場景的東西(東方財富、騰訊財經、Binance 等),與美股全市場日線這條問題無關;唯一沾邊的是 Vibe-Trading 與 QuantDinger 都用 `yfinance` 之類做示範,但兩份報告都沒有評估 yfinance 本身是否適合作正式數據層。

結論:這是一條全新問題,沒有重複調研。

## 逐一候選現況

### 1. yfinance(非官方 Yahoo Finance 包裝)

- **覆蓋**:免費抓 Yahoo Finance 網頁/內部端點的數據,退市股票的歷史數據通常在退市後仍可部分取得,但沒有系統性保證,亦沒有「已退市股票總表」這種正式清單——要自己從 SEC EDGAR 的 Form 25 之類另外拼湊退市股票名單。
- **除權除息調整**:有 `auto_adjust` 參數做拆股/派息調整,但沒有第三方稽核,調整方法不透明。
- **歷史深度**:視乎個股,一般可回溯到上市當日,但因為 2025 年 2 月 Yahoo 網站改版,近年常見抓取中斷、格式跳變的問題。
- **價格**:免費。
- **API/批量**:非官方端點,沒有官方批量下載服務,靠社群維護的 Python 包裝。
- **Python 支援**:原生 Python 包(`pip install yfinance`),是四個候選中最貼近「開箱即用」的一個。
- **授權/自用回測可否**:Yahoo Finance API 條款寫明只供個人使用(personal use only),`yfinance` 本身聲明與 Yahoo 無關、非官方、供研究與教育用途;多篇第三方文章指出用於商業產品有條款風險,但個人/非商業研究用途風險較低。**沒有官方書面授權可用於商業回測平台**,這點要留意。

### 2. EODHD(EOD Historical Data)

- **覆蓋**:官方文件講明覆蓋 70 個交易所,美股逾 26,000 個代碼(多數自 2000 年起),總計連退市在內約 80,000 個代碼;有獨立「Delisted Stock Companies」端點,退市股票歷史數據保留至退市日,可用 `delisted` 參數切換。
- **除權除息調整**:有標準的 Adjusted Close 端點,連拆股/派息紀錄一併提供。
- **歷史深度**:美股主力數據多數自 2000 年起。
- **價格**:有免費方案(每日 20 次呼叫,只限近一年數據),付費方案由 19.99 美元/月起。
- **API/批量**:REST API,亦有批量/整體下載選項(視乎方案)。
- **Python 支援**:有官方與社群 Python 客戶端。
- **授權/自用回測可否**:官方文件本身把回測/量化研究列為使用場景之一,付費方案下的自用回測條款上沒有問題;免費方案因為只給近一年數據,不足以支持長歷史回測。

### 3. Polygon.io(2026 年初起品牌改為 Massive)

- **覆蓋**:REST 端點可用 `active=false` 抓退市代碼列表,但第三方評論明確指出「退市代碼的歷史覆蓋尚可,但不能當作『某個時間點市場成分股名單』的替代品」——即退市數據存在,但不是為存活者偏差場景特別設計的時點式（point-in-time）成分股資料。
- **除權除息調整**:有拆股/派息端點,可自行做調整,或用已調整聚合數據。
- **歷史深度**:視方案而定,官方一般宣稱可回溯多年;確實年期沒有查到統一數字。
- **價格**:免費方案每月 100 次呼叫;付費方案由 29 美元/月起。
- **API/批量**:REST + WebSocket 串流,另有 S3 式 flat files 批量下載。
- **Python 支援**:有官方 Python 客戶端。
- **授權/自用回測可否**:條款容許自用分析/回測;品牌於 2026 年初改名為「Massive」,舊網域與 SDK 名稱是否全面過渡完成,本次查證沒有找到確切收尾時間,值得日後留意條款頁是否已更新為新公司名。

### 4. Tiingo

- **覆蓋**:官方宣稱覆蓋逾 80,000 個資產(美股、ETF、共同基金、中概股),Fundamentals API 明文包含在生與已退市、且有向 SEC 申報財報的代碼;沒有查到「退市股票總覆蓋率」的獨立數字。
- **除權除息調整**:End-of-Day API 有標準調整收盤價。
- **歷史深度**:官方宣稱最早可回溯至 1962 年(視個股)。
- **價格**:免費方案(每月 500 個代碼配額,可用 30 年以上歷史);付費方案 30 美元/月起。
- **API/批量**:REST API。
- **Python 支援**:有官方與社群包裝(如 `riingo`),亦廣泛見於 `pandas-datareader` 一類工具的內建支援。
- **授權/自用回測可否**:官方文件將回測列為典型使用場景,自用研究/回測沒有查到條款障礙。

### 5. Norgate Data

- **覆蓋**:官方定位就是「存活者偏差免疫」數據商,Platinum 方案含完整已退市美股歷史,退市代碼會加上退市年月後綴(例如 `JAVA-201001`),與現行代碼區分。
- **除權除息調整**:提供總回報調整價(total-return-adjusted),連拆股、派息、企業行動一併處理,是本次十個候選中在「這正是為了消除存活者偏差而設計」這點上證據最直接的一個。
- **歷史深度**:美股歷史覆蓋長,具體最早年份沒有查到統一數字,需另查官方頁面確認個別市場。
- **價格**:訂閱制,以半年或一年為單位、不自動續約;具體月費金額本次搜尋沒有取得,需查官方報價頁。
- **API/批量**:本體是 Windows 桌面應用程式「Norgate Data Updater(NDU)」,把數據寫入本機專有格式資料庫,不是雲端 REST API。
- **Python 支援**:有官方 Python 套件透過本機 NDU 資料庫讀取數據,亦有與 Zipline 等回測框架的整合套件;**前提是要在 Windows 環境跑 NDU 常駐維護數據**,非 Windows 環境(例如 Linux 伺服器上跑 vectorbt)要另外設法(虛擬機或定期匯出)。
- **授權/自用回測可否**:官方明文支援量化研究/回測用途,是本次十個候選裡「因為抵抗存活者偏差而設計」最貼題的一個,但平台形態(桌面應用 + 本機資料庫)與雲端/伺服器化的回測平台架構有整合成本。

### 6. Alpaca Market Data

- **覆蓋**:官方沒有明文交代退市股票的覆蓋政策,本次查證沒有找到「Alpaca 是否提供退市股票歷史數據」的明確答案——這是一個查不到的項目(見文末)。
- **除權除息調整**:官方文件有拆股/派息相關端點,細節(是否自動生成調整後收盤價)沒有進一步核實。
- **歷史深度**:官方宣稱日線/分鐘線歷史數據普遍覆蓋 7 年以上,部分代碼 5 年以上。
- **價格**:免費方案(Basic)已含歷史日線數據,但即時數據只限 IEX 單一交易所;要 CTA/UTP 全市場 SIP 數據才需付費「Unlimited」方案。
- **API/批量**:REST + WebSocket。
- **Python 支援**:有官方 `alpaca-py` SDK。
- **授權/自用回測可否**:Alpaca 定位是券商 + 數據一體,免費歷史數據不強制要求真實入金交易帳戶,但生態設計上與其經紀業務綁定;純粹當「歷史日線數據源」用是否符合條款,本次沒有查到明確反對聲明,但也沒有查到明文歡迎「與 Alpaca 交易帳戶無關的純數據轉售/回測平台商用」的條款字眼。

### 7. Databento

- **覆蓋**:官方「Security Master」宣稱覆蓋逾 310,000 個在市與已下市的股票、ETP、存託憑證等,明文標榜其數據集容許「不受存活者偏差與前視偏差影響」的回測。
- **除權除息調整**:美股數據集含標準化的企業行動/調整處理(細節需查個別 dataset 文件核實)。
- **歷史深度**:視乎個別數據集(例如 XNAS、XNYS),官方沒有統一的「全部歷史多長」單一答案。
- **價格**:新用戶送 125 美元試用額度;有 Standard 月費方案(2025 年 1 月起新增,美股 OHLCV 及相關數據可無限量取用其完整歷史),另有以用量計費的一次性歷史數據購買選項;點名的「US Equities Mini」方案為 200 美元/月。
- **API/批量**:REST + 歷史數據批量下載,以逐個 dataset/venue 為單位授權。
- **Python 支援**:有官方 Python 客戶端。
- **授權/自用回測可否**:官方明文以回測場景作賣點,自用回測沒有查到條款障礙,但要留意月費方案是否涵蓋你需要的具體 dataset(例如 XNAS/XNYS 各自可能分開計價)。

### 8. Nasdaq Data Link(前身 Quandl)

- **現況**:本次查證確認平台在 2026 年 5 月仍在正常運作,沒有查到官方宣布關閉或大幅收縮的消息。
- **定位**:本身是一個數據市場(marketplace),Sharadar 是掛在其上其中一個數據集供應商(見下一項);兩者條款分開看。
- **價格/覆蓋**:視個別掛牌數據集而定,沒有獨立於 Sharadar 之外、專門針對「美股日線全市場」的自家數據集在本次查證中被識別出來。

### 9. Sharadar(可經 Nasdaq Data Link 或官方 sharadar.com 直接訂閱)

- **覆蓋**:官方「Sharadar Equity Prices(SEP)」宣稱覆蓋逾 21,000 個在市與已下市代碼,歷史回溯至 1998 年;另一款「North American Equity Prices」宣稱覆蓋逾 32,000 個在市與已下市代碼,並明文標榜「幾乎完全沒有存活者偏差」。連退市原因、代碼變更等企業行動細節一併記錄。
- **除權除息調整**:資料庫本身即以總回報調整為設計目的之一。
- **歷史深度**:主力數據回溯至 1998 年前後(視資料庫版本)。
- **價格**:第三方轉售商(如 QuantRocket)報價約 49 美元/月起(具體視方案與是否經 Nasdaq Data Link 或官方直售)。
- **API/批量**:經 Nasdaq Data Link API,或第三方平台(QuantRocket 等)包裝存取;亦有批量下載。
- **Python 支援**:Nasdaq Data Link 官方 Python 客戶端 `nasdaq-data-link`(前身 `quandl`)可直接拉取;第三方平台亦有各自 Python 介面。
- **授權/自用回測可否**:官方條款(經 QuantRocket 轉載的 Sharadar License Terms)明文區分「非專業使用」與「專業/機構使用」——如果用途涉及任何專業活動,要訂閱對應的專業或機構授權;另有一條特別條款:**不容許在未經 Sharadar 書面同意下,公開發布任何關於這批數據「可用性/適用性」的測試或評估結論**(即不能公開講「我測過 Sharadar 數據,結論是……」)。這對內部自用回測沒有直接限制,但對外分享測評結果要注意。轉售/在組織內外重新散布數據亦要另購對應授權。

### 10. Financial Modeling Prep(FMP)

- **覆蓋**:有獨立「Delisted Companies API」,列出代碼、公司名、交易所、IPO 日與退市日(例如 Forge Global Holdings 於 2026-03-02 退市的紀錄有被官方文件引用);官方文件亦提供「如何處理已退市公司與歷史代碼」的專門指引。
- **除權除息調整**:歷史行情 API 支援日線至分鐘線(1 分鐘至 1 小時)多個粒度,可按日期範圍與調整方式取得數據。
- **歷史深度**:官方沒有統一交代最早年份,視個股與方案而定。
- **價格**:免費方案有 30 天 500MB 流量上限;付費方案 Starter/Premium/Ultimate/Build/Enterprise 各級距,以流量(20GB 至 1TB+)計價,而非以呼叫次數計價。
- **API/批量**:REST API。
- **Python 支援**:有社群與官方推薦的 Python 包裝範例(GitHub 上有官方引用的第三方庫)。
- **授權/自用回測可否**:官方文件把回測列為典型使用場景,免費方案流量細(500MB/30 天),做全市場日線歷史回測大概率要升付費方案;具體商業授權條款細節(可否用於對外提供的付費產品)本次沒有深入查核。

## tradingview-screener 套件現況

`tradingview-screener`(PyPI:`shner-elmo/TradingView-Screener`)截至查證日仍在活躍維護:最新版本 3.2.0 於 2026 年 5 月發布,累計下載逾 128 萬次(近 30 日約 17 萬次),文件網站由 GitHub Actions 每日自動更新以跟上 TradingView 端的欄位/市場變動,減少寫死數值的脆弱性。技術上仍可用作選股宇宙來源。**但要留意 KARST-010 已指出的結構性風險沒有改變**:它走的是 TradingView 未公開的內部端點,不是官方 API,條款與封鎖風險由使用者自行承擔——這點與套件本身「仍在維護」是兩回事,前者是工程活躍度,後者是法律/穩定性風險,活躍維護不等於端點風險消失。

## 查不到的項目(需另外查證,本報告不代拍板)

1. **Alpaca 是否提供已退市股票的歷史數據**——官方文件沒有正面交代,是本次十個候選中覆蓋政策最不透明的一個。
2. **Norgate Data 的具體月費/年費金額**——官方報價頁需另外查核(訂閱制,半年或一年為單位)。
3. **Polygon.io 品牌過渡至「Massive」是否已在條款頁、SDK 命名、網域上完全收尾**——本次查證只確認品牌於 2026 年初開始過渡,收尾進度未核實。
4. **多個供應商的「歷史最早年份」統一數字**(Polygon、Databento、FMP、Norgate)——官方文件普遍寫「視個股/方案而定」,沒有一個單一數字可引用。
