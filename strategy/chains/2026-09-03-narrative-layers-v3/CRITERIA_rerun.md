## 3. 價格(改動一:單一價格庫)

### 3.1 來源

全部 343 家的價格**只由 `data/prices/daily/`(KARST-171 單一價格庫)取**。
不再讀 `experiments/2026-09-02-timing-sweep/data/daily_close.parquet` 的個股欄,
不再讀 `experiments/2026-09-02-narrative-layers-v2/data/new_close.parquet`,
不再讀生產庫 `karst.sqlite`(全程唯讀,只核雜湊)。

**版本記法**(D-160:同一個代號兩日抓回來的 `adj_close` 必然對不上帳):
本票在 `out/price_source_version.json` 記低 `manifest.csv` 的 SHA256 首 16 位、
`fetchedAt` 的最早與最晚值、以及實際用到的段數。復現本票的數字靠這個版本記錄,
不是「再抓一次」。

### 3.2 代號 → 價格段(寫死,不看數揀)

`manifest.csv` 內同一個代號可能有多段(代號重用,例如 PARA)。取段次序:

1. 只考慮 `ticker` 等於鏈表那個代號的段(**`series_role = alias` 的段照收**——
   本票要的是「這個代號的價格」,不是「這個實體的唯一序列」;GOOGL 就是 alias
   而它正是鏈表用的代號);
2. 取涵蓋該切片回報窗的段(`valid_from ≤ 窗起` 且(`valid_to` 空白 或 `valid_to ≥ 窗終`));
3. 無一段完全涵蓋,取與回報窗重疊日數最多的段;
4. 仍相同:`series_role = primary` 優先 → `rows` 較多 → `entity_id` 較細。

**庫內完全取不到的代號一律缺席**,逐個列名入報告附錄。已知有三個:
`GTBIF`(場外報價,E3 剔)、`PXD`(2024 年被併,庫內無退市公司)、
`XOM`(代號今日指向 2026 年新設控股公司,未交年報,I3 剔——見價格庫 README 第六節)。
**`XOM` 這一個是相對 v3 的倒退**(v3 由舊面板取得到它),照實記,不作補救。

### 3.3 調整因子自算(D-160)

對每一段,自算調整因子

```
f_t = adj_close_t / close_t          (累計除息因子,相對於已拆股調整的 close 基準)
p_t = close_t × f_t                  (入數用的已調整價)
```

日回報用 `p_t` 算。因子摘要(每段的 f 首值、末值、最小、最大)落 `out/adj_factor_audit.csv`。

**誠實講明(不可略):** `f_t` 由本庫兩欄相除得出,所以 `p_t` 在數值上等於 `adj_close_t`,
這不是另一條獨立的調整路徑。自算的意義只有一個——**把因子連同庫版本凍結落檔**,
令這一次運行復現得到;D-160 指出的問題是 `adj_close` 會被日後的派息追溯改寫,
凍結因子與版本正是針對這一點。要一條真正獨立的調整路徑,要用拆股與股息事件表重建,
那是另一張票的範圍,本票不做。

### 3.4 基準

`SPY` 與九隻板塊 SPDR **仍然取自 `experiments/2026-09-02-timing-sweep/data/daily_close.parquet`**。
理由兩條:①單一價格庫按設計不收 ETF(README 第六節,ETF 連 CIK 都不在證監會代號快照);
②刻意沿用 v3 同一條基準序列,令新舊之差**全部來自個股價格**,不摻基準的改動。
板塊映射照 v3:Communication Services → XLK、Real Estate → XLF,所有切片同一個映射。

## 4. 子行業與板塊補缺(改動二:只抓缺的)

1. 只對現有 meta(`ticker_meta.json` + `ticker_meta_new.json`)**缺 `industry`** 的公司抓
   yfinance `.info`。普查已知是 **85 家**,以實跑為準,上限 85 家。
2. 抓取參數照價格庫 README 第四節的教訓:逐家抓,每家之間**退讓 1.2–2.0 秒**;
   失敗者重試一次(退讓 1.5–2.5 秒);仍然失敗即記 `fail`,不無限重試。
3. 存 `out/industry_fill.csv`:`ticker, industry, sector, status, fetchedAt`,附抓取日。
4. **`sector` 一併採用**(同一次呼叫零額外成本)。理由寫在前面:若只補 `industry`
   而不補 `sector`,新補的 85 家會只用 SPY 單因子做殘差、原有的 258 家用兩因子,
   兩批公司受到系統性不同的待遇,新舊之差就分不清是價格補缺還是殘差口徑差別。
5. 抓不到 `industry` 的公司仍然缺席(第 3 節的規則不變:要有價格**又**要有子行業才入數)。

## 5. 量法(照 `CRITERIA.md` 第 3、4、5、6、7、8 節,一字不改)

- 殘差:窗內 OLS `r_i = a + b1·r_SPY + b2·r_板塊ETF + e_i`;無板塊資料者只用 SPY。
- 殘餘相關:Pearson,`min_periods=150`。
- 三組配對 G1 / G2 / G3 / G0 定義不變。
- cluster bootstrap:以層為抽樣單位,`B = 2000`,種子 **20260902**,百分位法 95%;
  單次重抽若 G1 或 G2 少於 20 對則棄用。
- 隨機重貼標籤運氣帶:`B = 2000`,種子 **20260903**,報 2.5 / 97.5 百分位與實測值百分位排名。
- 等效獨立層數 `N_eff = N² / ΣR_ij`,同期九隻板塊 ETF 作對照。
- AMI:`adjusted_mutual_info_score(子行業, 層標籤)`。
- **配對數門檻:任何 arm × 切片,G1 或 G2 配對數 < 100 即判量不出**,
  不得用來支持「存在」,亦不得用來支持「不存在」。

## 7. 判詞(票面已寫死,本檔照抄,不改)

判詞只看 **甲版(全)`manual_v22_full` × 切片 2023-06-30** 一格:

- **存在** ⟺ 該格 cluster bootstrap 95% 置信區間**下限 > 0**
  (進入 D-159 第二步:開乙版新資訊源票);
- **不存在** ⟺ 該格 `G1 − G2 < 0` 且置信區間**上限 < 0**;
- **其餘一切情況 = 量不出**(鏈層降為研究用途,不開新資訊源票)。

硬前提:該格 G1 與 G2 的配對數皆須 **≥ 100**;任何一個不足即**直接判量不出**,
上面三個分支都不適用。

**2025-06-30 切片只作附錄,不入判詞。** 2015 / 2019 兩個切片與連續窗同樣不入判詞。

v3 `CRITERIA.md` 第 10 節另外三項條件(`N_eff` 減板塊 ETF ≥ 1.0、`G1 − G2` 符號在可判
切片一致、配對數 ≥ 100)**照樣逐項報出來作透明度**,但**不改**上面這條主判詞——
票面寫死的就是置信區間下限這一條。

## 8. 誠實聲明(入報告首段;v3 七項照搬,加第 8 項)

1. **這仍然是一張事後編的表。** v2.2 的 65 條鏈、343 家成員,是 2026 年的人回望
   2022–2026 之後編的;哪條鏈存在、哪家屬哪條,全部帶事後眼光。甲版只證「這種分法
   有解析度」,證不到「當年分得出」。
2. **入位日仍有一半是近似。** v2.2 的 `valid_from` 約六成標「近似」;兩個主切片照收,
   即主切片的成員資格本身仍然帶入位日誤差。
3. **宇宙仍然是倖存者。** 補缺補得回的,全部是今日仍在市的公司;除牌的一家都補不回
   (價格庫 README 第五節第 2 點:代號來自證監會今日快照)。另外庫內取不到 `XOM`、
   `PXD`、`GTBIF` 三家,其中 `XOM` 是相對 v3 的倒退。
4. **子行業不是官方 GICS。** 用 yfinance 的 `industry` 欄作近似;XLC 與 XLRE 不在日線檔內,
   通訊服務對 XLK、房地產對 XLF,所有切片同一個映射。
5. **乙版不重跑。** 本票只答「補齊價格與子行業之後,事後表上的解析度撐不撐得起自己的
   置信區間」。「當年分不分得出」那條問題,v3 已判不存在(A-042 `overturned`),本票不碰。
6. **語意模型那條腳註不適用**(乙版不跑),但 v3 的結論照舊掛在案上。
7. **2023 切片之後的十二個月含 AI 敘事大牛市**,兩個主切片一律分開報,不合併。
8. **價格來源換了,舊新不完全可比。**(本票新增)v3 用的是
   `daily_close.parquet` + `new_close.parquet`(`auto_adjust=True`,抓取日在 2026-09-02),
   本票用的是單一價格庫(`auto_adjust=False` 加自算因子,抓取日 2026-09-03)。
   D-160 已證 `adj_close` 每次派息會被追溯改寫——同一個代號兩日抓回來必然對不上帳。
   所以**新舊兩組數的差,一部分來自補缺,一部分來自調整因子的重新縮放,本票分不開這兩者**。
   並列表只用來看方向與量級,不可當作「補了 N 家就多了 X」的因果讀數。
