## 1. 交付目的與邊界

讓 Agent 取得可靠的必要資訊，實際看圖後形成條件交易計劃。新增工具須回答既有流程尚未解決的問題；同義訊號、畫面豐富或功能評分較高都不足以支持加入。不設全域指標投票制。若現有價格、量、MA、ATR、支阻及可取得的相對強弱比較已足夠，就直接交付研究。

月線看長期背景；週線與日線同時判斷位置、結構及 setup；需要更精確的觸發才補 4 小時。沿用基本面、公允價值、敘事／市場定價、技術走勢的分工。SMC 的 premium／discount 是選定價格區間的位置，不是公司內在價值高低；200MA 亦不是價值底線。

**程式必須通用,倉內不准一次性腳本**：程式只住 karst/ 套件,代號與日期由參數傳入,生產檔名與碼內不寫死股票身份;參數化測試 fixture 可含代號及可信預期值,不逐股複製腳本;探索與除錯碼放倉外 scratchpad,不 commit。

## 3. T0：來源與時間可靠性（SMC 驗收前置）

1. 選源先比證券身份、復權／交易時段／資料口徑、可用時間與完整性，再處理歷史覆蓋。最新研究選最新適用快照；歷史重播只可用當時已取得的證據，不能拿今日快照截斷後假稱當時可得。
2. 不因舊快照較長而蓋過新價格。需補長歷史時，僅合併相容口徑、明確處理重疊，保留每段來源；無法相容便分開或報缺口。
3. bar 完成狀態根據來源語義、取得時間及實際交易所日曆／收市時間判定，涵蓋時區、假期、提早收市。未知不可升為已確認；週／月最後一期亦同。
4. 定向回歸：相同長度新舊快照、較長舊／較短新、盤中快照隔日重用、歷史可用時間截止、週月未完成 bar。取證路徑若改動，遵守 D-178 相關回歸要求。
5. BE 已知回歸樣本可放參數化 fixture：較新來源的 2026-09-17 收市 280.76／量 14,236,326；不得被較早盤中 280.08／11,493,859 蓋過。數值是除錯樣本，非本輪新投資判斷。

本輪已看到兩個必核點：
- leg(size) 在目前 bar 判定較早的 pivot，標記再畫回 time[size]。其 leg 規則不等同 Karst 既有左右對稱 pivot；要明示採用哪套定義，不聲稱兩者逐點相同。

### 4.2 先交結構最小版

首輪只要求 confirmed swing／BOS／CHoCH、前高低與 sweep，以及沿用現有支阻的突破／回踩判斷。先核對它們相對現有 pivot 分析增加了甚麼；internal 多層結構、Order Block、FVG 的定義保留作參考，僅在案例證明能補足位置或失效判斷時實作，不以完整複製 LuxAlgo 為完成條件。SMC 也不豁免增量用途檢查。

| 能力 | 可重算定義與狀態要求 |
|---|---|
| Swing structure（首輪；internal 按缺口選用） | pivot 方法、窗口、HH／HL／LH／LL、趨勢狀態明確；BOS／CHoCH 以已確認 level 的突破規則判定，預設收線確認。首次建立結構及方向不明不得硬標 CHoCH。 |
| 等高／等低與 liquidity sweep | 容差按 tick／ATR、間距可配置；先有當時已確認的 level，再有越界與收回。初版可用收線 bar 的 wick 越界、close 回到原側；跨 bar reclaim 另有窗口。未收回、失效與尚未確認分開。 |
| Order Block（有條件候選） | 明定結構突破前如何選候選反向 K 線、body／wick 邊界、量／波動篩選及 mitigation 規則；active、touched、invalid 狀態可追溯。不要把每根反向 K 線都稱機構買賣區。 |
| FVG（有條件候選） | 三根 K 線的價格不重疊區間為基本候選；閾值與額外 displacement 條件版本化。標示方向、區間、首次觸碰、部分／全部填補及失效；同週期／跨週期分開驗證。 |
| 區間、趨勢線與突破回踩 | 沿用 pivot、支阻聚類及通道設計；程式候選和 Agent 綜合區域分清。趨勢線錨點須在判斷時已可知，突破後仍要判斷回踩／失守。 |

事件至少保存 anchor_time、confirmed_at、timeframe、方向、價位／區域、定義與參數版本、source refs、狀態轉換及失效條件。舊 bar 上的繪圖錨點不等於當時已可交易；provisional 可供觀察但不得混入 confirmed 歷史績效。

驗收用逐步增加資料的 prefix replay：截至某時已確認的事件不可因未來 bar 被偷偷改寫；後續觸碰／失效應追加狀態。涵蓋趨勢、箱體、假突破、缺口、未收市和跨週期案例。與 TradingView 差異按資料／設定／定義／確認時間歸因；不能為了圖形一致而保留前視。

## 5. T2：有條件候選（不預設實作、不阻塞研究）

以下是備選能力及必要時的驗收規格，不是建置待辦。新增前以既有研究案例做輕量對照，具體說明：

1. 現有工具缺少哪項資訊，是否重複現有價格／量／MA／ATR／RS。
2. 加入後能改善哪個 setup、觸發、失效、等待決定，或可觀察地減少漏看／錯判；不以訊號數量作成績，也不要求為加指標展開大型回測。
3. 資料與計算可核實，新增噪音及維護負擔合理。無法說明實際用途便不加入；小量案例只支持試用，不能宣稱已證明 alpha。

| 狀態 | 能力 | 對投資判斷的用途／驗收邊界 |
|---|---|---|
| 按缺口選用 | Anchored VWAP | 以業績、重大缺口或已確認轉折作可解釋錨點，觀察事件後成交加權價格。保存錨點理由及當時可知時間；它不是現有持有人實際成本。不同 bar 粒度結果可不同，日線近似不可冒充盤中精算。 |
| 按缺口選用 | RS 對大市／行業／同業 | 同期、同口徑比較 20／60／120 交易日表現及 RS 趨勢；基準與同業集合明列。RS 不等於 RSI；沒有完整排序母體便不報全市場百分位。 |
| 按缺口選用 | RVOL、ATR 與波動收縮 | 擴展現有量比／ATR，不重建；盤中量需與相同時段比較或清楚標示。ATR 正規化、BB width 等協助判斷整理、伸延及止損尺度，收縮本身不等於會向上突破。 |
| 按缺口選用 | Volume Profile：POC／VAH／VAL | 固定區間及交易時段有明確理由；需足夠低週期成交資料或可核對輸出。日線成交量按收市價分箱不是精確 Volume Profile。資料不足報缺口，不阻塞首輪交付。 |
| 按情境啟用 | RSI／背馳、ADX、MACD、Donchian 等 | 作動能、趨勢或區間補充；參數與 warm-up 一致。由相同價格衍生的多項指標不可當多份獨立證據。 |

AVWAP 與 Volume Profile 定義參照 [AVWAP](https://www.tradingview.com/support/solutions/43000669764-anchored-vwap-drawing-tool/)／[Volume Profile](https://www.tradingview.com/support/solutions/43000502040-volume-profile-indicators-basic-concepts/)。Profile 的 value area 是成交分布區，不能和基本面「合理價值範圍」共用含義。

**本輪腳本取捨（靜態評閱，未跑平台或回測）**：Squeeze Momentum 只作波動／動能缺口的候選，先核對 BB 倍數錯用 KC 倍數的舊版問題；Auto Chart Patterns 暫不整合，先看現有 pivot／趨勢線與 LLM 是否真的漏看；兩套 FUTU 指標目前不納入，價格／量的衍生分數不可命名為已驗證的主力、游資或散戶資金。先前功能適配評分不是投資績效證據。

Footprint、CVD／真實 order flow 先列資料依賴，不用 OHLCV 偽造買賣方逐筆流量。指標可逐步增加，但每次新增須指出其增量資訊、失效情境及對交易計劃的影響；數值驗算通過不代表已證明投資超額回報。

## 6. TradingView：可選資料入口與比對台

2026-09-18 查到 [TradingView 官方 MCP Beta](https://www.tradingview.com/mcp/docs)：Essential 或以上付費方案、非試用；OAuth；端點 https://mcp.tradingview.com/mcp 。文件列出 OHLCV、技術快照及 screener。本對話尚未暴露此連接。

僅在能填補資料／比對缺口時安排連接，不因已有訂閱而新增依賴；亦不作首輪前置。需要時以公開市場資料做 read-only smoke test：識別證券、拉日／週／必要盤中資料、核對收市與指標的時點／復權／時段，再決定加入取數 adapter。研究不藉此讀私人帳本；連接是否成功及實際工具能力以當場驗收為準。

官方目前所列工具不能據此推定可執行任意 Pine、讀取所有付費／自訂指標或截取圖表。帳戶已有訂閱不是 Karst 已取得這些能力的證明；也不把綜合 Buy／Sell rating 當本研究判斷。

既有材料足夠開始，不主動要求更多腳本。僅在具體缺口出現時，可選補充：
- 原始 TradingView 腳本連結或 Pine 檔；優先 AVWAP／成交分布、RS／行業輪動、VCP／突破回踩。
- 常用參數、週期、代表圖，以及它幫助哪個判斷。
- 未公開源碼的工具用獲授權的輸出與說明比對，不假設可取得內部算法。必要時可用 [圖表 CSV 匯出](https://www.tradingview.com/support/solutions/43000537255-how-to-export-chart-data/)，先核對實際包含欄位與已載入範圍；不假設所有 boxes／drawings 都會匯出。

## 7. T3：研究、圖表與發布整體驗收

1. 重用既有 service／chart／MCP image 路徑，按需延展結果；不為每個指標各建一套協議。Agent 必須實際讀到圖，並用同源數值核對。
2. 保存計算與事件供 Agent 查閱；人類圖表只畫影響判斷的趨勢線、支阻與交易區域，其餘可按需展開。合理價值區間來自正式估值且註明日期／情境；勿混入 SMC discount 或 VP value area。
3. Agent 說明趨勢／位置、setup、觸發、失效、目標或不做；可否決程式候選但要在研究記錄保留理由，不要求用戶讀所有算法明細。
4. 用 BE 加另一隻不同形態的既有研究股票作通用端到端驗收：取證 → 計算 → 實際讀圖 → 主研究／覆核 → 正式版本保存 → 人類摘要 → Pages。保留未覆核／資料不足標示；不改寫舊發布。
5. 新事件先重算受影響項目，沿用仍有效的證據；舊結論不是預設正確。對用戶先呈現「改變了什麼、建議有否改變、為什麼」，不要求每天重讀全部原料。
6. 比較現有價格／量／MA／ATR／支阻及可取得的 RS 基線與新增 SMC 的決策差異，包含無訊號與失敗例子；未見用途的細項可不啟用並記錄原因，不為保住指標而強行製造交易。後續前瞻記錄再評估效益。
