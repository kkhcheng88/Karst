# 獨立投研工作台設計與交付計劃(v1,2026-09-14;D-181)

> 本檔是可實作設計與交付順序,不是已完成的系統。策略正本為[投資決策模型](../投資決策模型.md),分析細則為[六層紀律](六層分析紀律-v1.md)。本輪交付設計、對齊規格與 KARST-240;實作狀態以[地圖](../四類注地圖.md)為準。

## 一、產品與界面

**2026-09-18 呈現補充（用戶已確認）**：近期快速交付是「用戶在對話要求分析 → Karst 保存／發布 → 客戶端直接呈現並支援追問」。自然語言回答遵循《投資委託》v1.3 第五節，該節是呈現正本；下表為應涵蓋的資訊，不是必須逐格展示的對話版面。HTML、獨立收件匣與通知可後續接，不阻塞對話交付；本次未改現有 renderer 或排程。完整研究記錄保留反證，畫面不另設固定「最強反證」欄目。

第一個可用產物是通用股票頁。輸入代號及資料截止時間,產生來源可追查的獨立評級、內在價值、期間目標與條件式計劃;換公司不修改程式。之後加入觀察名單、每日差異、模型組合及市場掃描。

| 區域 | 直接回答 |
|---|---|
| 首屏 | 研究評級、執行狀態、主要理由、關鍵假設、最強反證、改變行動條件、較上次變化 |
| 估值 | 今天的基準情境每股公允價值及悲觀／樂觀範圍、現價折讓、指定期限目標價與計算依據 |
| 價格 | 日週月位置、關鍵支撐阻力、200 日 SMA、通道／突破回踩、價量動能、確認／失效 |
| 計劃 | 入場區與確認、目標與退出、時間、每股／百分比 R&R、壓力情境、下次驗證 |
| 依據 | 六層推理、原文定位、來源時間與缺口;點開可看原文 |
| 每日變化 | 哪個來源更新、哪個假設改了、評級／價值／計劃有何影響,或只有價格改變 |

首版生成 HTML,目前僅定本地可讀產物;手機遠端存取與自動發布另作交付配置,不聲稱已有部署。Markdown 用於可讀研究內容,結構化契約服務機器更新;頁面不顯示逐格「已量度／未量度」標籤。覆蓋不足要說明對決策的影響。

## 二、職責、上下文與權限

| 執行邊界 | 可讀 | 產出 | 不可讀／不可做 |
|---|---|---|---|
| 取證與計算 | 公開資料接口、本地證據、清理後報告、配置 | 原文快照、數列、估值與 TA 計算 | 不取私人帳戶與下單資料 |
| 獨立研究 | 清理後委託、證據包、相關研究發布及市場／產業假設 | 評級、情境、條件計劃與不可改寫發布 | 不讀真實／模型組合帳本、成本、盈虧或交易工具 |
| 模型組合 | 已發布研究、模型委託、模型自己的帳本 | 紙上配置決策、模擬訂單與帳本事件 | 不讀／操作真實帳戶,不修改研究原版 |
| 評估器 | 凍結發布、模型帳本、之後公開的實際結果與市場數據 | 分層成績與錯誤歸因、後續方法建議 | 不回填原判斷／原成交,不直接改動生效方法 |

開發 agent 可以讀 repo 的管理文件;正式研究 worker 必須新建上下文,由程式按允許清單組裝,不自動載入 CLAUDE、HANDOFF、.kira、全倉目錄、原聊天或模型帳本。只傳入經清理的研究委託、核准的方法摘錄、來源包與所需研究版本。文件內容是待分析資料,其中的指令不能擴張工具權限。

MCP/API 權限在執行端依具體工具／方法設允許清單,不能把含帳戶與交易工具的整個券商 server 無限制交給研究角色。公司公開機構持股及內部人交易可用;名稱含「持股」不代表私人資訊。補查要求經同一取證入口落地,保留來源與公開時間。

inbox 先進隔離區並做來源分類、個資／帳戶資料檢查;含實際持倉等內容不送研究 LLM,改用已清理的研究副本。難以辨認的圖像／混合文件先隔離,不能讓研究模型讀過再聲稱盲分析。用戶假設與外部事實不同欄位。

模型組合與評估器可以研究「為什麼錯」,但新方法只在登記生效後影響新發布。研究 worker 不靠私人盈虧回饋合理化特定股票;方法改善以有版本的通用規則或核准案例輸入。

## 三、研究工作流與估值契約

1. 接受 security_id、as_of、研究委託版本及 initial／update 模式,解析公司身份及適用申報形式。
2. 取證器查快取、來源訂閱與差異,產生來源清單、缺口及固定輸入版本。
3. L1/L2 和 L3 讀原始證據;L5 讀程式產生的價格結構。反方先獨立形成替代解釋。
4. L4 以 L2/L3 經營情境建估值,可回讀原文、補查或要求修正;反方再審各層。
5. L6 回應最強反證,決定研究評級、目標與條件式計劃;不用票數或平均分代替裁決。
6. 驗證結構、數字、引用、時間與依賴後發布。重要證據矛盾未解時給出受約束的結論及下一步,不用無限辯論等待完美。

強模型直接接觸原文;便宜模型只作可核查轉換,程式負責數值計算與限制。記實際 provider、model_id、推理設定、prompt／method 版本、用量與成本,不以「Opus／GPT」簡稱代替。降級需明示配置與原因,不靜默替換關鍵判斷模型。首版設有限補查／重評輪數與成本預算,耗盡顯示缺口及影響,不把截斷當完成。

**內在價值為 L4 核心輸出,由 L3 基本面推導。**

| 欄位 | 定義 |
|---|---|
| valuation_date | 今天公允價值的估值日,與資料截止時間分開 |
| method／calculation_version | DCF、剩餘收益、分部估值等適用方法與計算版本 |
| operating_scenarios | 悲觀／基準／樂觀的收入、利潤、再投資、融資、稀釋及每股現金流 |
| fair_value_base／range | 估值日的每股基準公允價值與情境範圍;基準由經營假設推導,不取兩端簡單平均 |
| market_price／price_at | 同一證券與幣別、明確時間的市場價格 |
| price_to_value_gap | 基準值有效且為正時,1 − 現價÷基準公允價值;另示各情境,不假定此折讓會回補 |
| implied_requirements | 固定其他假設時現價所要求的成長、利潤率或期限;不是唯一反解 |
| target_date／target_scenarios | 指定中期期限的價格情境,以屆時經營／估值／催化劑及仍未被市場承認的風險橋接 |
| expected_distributions | 期間預期現金分派獨立記,供總回報估算;不能在目標價與回報重複計入 |
| sensitivity／invalidators | 主要敏感參數、資料缺口與令估值失效的條件 |

內在估值的方法定義參照 [Damodaran 估值導論](https://pages.stern.nyu.edu/~adamodar/pdfiles/eqnotes/ValIntroSpr22.pdf);以下期間目標與執行規則屬本系統設計。

DCF 的基本橋接為:企業現金流折現 → 企業價值 → 扣債務及其他請求權、加適用非營運資產 → 普通股價值 → 稀釋後每股價值。FCFF／FCFE 與折現率一致,股權薪酬、稀釋及終值不漏算／不重算。不能可靠估點值時保留範圍或條件估值,明列未知。

今天的內在價值不直接等同六個月後的股價目標。不能只把今天 DCF 加上折現率就聲稱市場屆時會到價;目標價需解釋實現路徑與期限。技術阻力是計劃的另一個約束,不是企業公允價值的替代。

## 四、資料物件與正本

實體身份、來源版本與論點是核心,資料夾只是人看的擺法。發行人與交易證券分開,避免同公司多股類、ADR、改代號或幣別混用。

| 物件 | 最低欄位／關係 |
|---|---|
| entity／security | 穩定 entity_id、類型(公司／產業／市場主題)、security_id、issuer_id、交易所、幣別、代號有效期;鏈位與角色可多個 |
| source_version | 邏輯 source_id、不可變 source_version_id、完整內容 hash、來源／作者／URL、公開時間、取得時間、所述期間、修訂關係、原文位置 |
| source_observation | 抓取嘗試時間、來源游標、成功且無變／新增／失敗／撤回／覆蓋未知,指向 source_version |
| derived_artifact | 原始 hash、解析器版本、標準化文本／表格 hash、段落或表格定位映射 |
| claim／assumption | id、version、scope、事實／作者預測／系統推斷／用戶假設、適用期間、來源定位、失效與覆核條件 |
| relationship | from／to、方向、類型、經濟機制、暴露程度／未知、有效期間、證據及版本;產業卡與公司共用 |
| thesis | thesis_id／version、公司／證券、機制、預期差、必要假設、反證、期限、驗證事件 |
| assessment／phase | layer、entity、timeframe、判斷／狀態、input_refs、assessed_at、data_as_of、confirmed_at、method_version |
| publication | publication_id、舊版引用、評級／計劃、固定目標日、輸入版本集合、各模型與方法版本、發布時間、待更新項 |
| subscription／dependency | 前者監測新來源和事件;後者連來源／假設版本到評估層、論點及發布,用於失效路由 |
| job | 去重鍵、受影響物件／層、目標輸入版本、狀態、重試次數、租約／版本檢查、錯誤與完成紀錄 |
| model_ledger／evaluation | 引用已發布判斷、模型委託、決策／模擬成交時間與價格;評估固定原目標及方法版本 |

published_at、observed_at／fetched_at、data_as_of、fiscal_period、effective_period 不互相代替。截止前公開的未來指引合法;截止後才公開的實際結果不合法。未知公開時間不倒填進歷史包;回顧分「市場當時已公開」與「本系統當時實際取得」。

同一內容 hash 可有不同來源紀錄,去重不抹掉作者、發布位置或修訂鏈。同一來源反覆抓到相同內容只追加觀測／更新游標,不製造新研究版本。來源修正值新增版本,日常用最新適用公開值,凍結歷史依原協議。

## 五、儲存與發布一致性

第一版用本地檔案、Markdown／JSON 發布包、SQLite。大型原文與行情不入 git,既有原料按 D-134 先查唯一副本;新 hash 或衍生內容才新增。實際可回放需原文與清單的持久備份,不能靠只有連結或重新下載最新頁面。

- **證據正本**:不可改寫的原始內容與來源版本 manifest;解析文本是衍生物,有原始 hash 和解析版本。
- **研究正本**:每次完整的不可變發布包(cards/releases/<publication_id>/),含 manifest.json(身份、版本、依賴)、card.md(分析內容)與計算結果。MD 與 JSON 分管不同欄位,由同一份驗證後結果一次產生。
- **目前畫面**:公司／產業／市場卡的最新視圖與 HTML 由發布包生成,不能手改視圖而讓評估引用另一份內容。人工修訂也經發布流程產生新版。
- **索引**:實體、來源及研究依賴可由登記清單／發布包重建。
- **持久營運狀態**:任務、游標、重試、發布指標、模型帳本與評估登記不能假裝全部能由 Markdown 重建。SQLite 備份及不可改寫帳本事件／發布登記需一起保存。

SQLite 表按物件拆,來源／研究索引與持久營運狀態分開標註。單一提交者配版本檢查,研究 worker 可並行讀／產出候選,不各自覆寫卡片。是否改 PostgreSQL 按多主機寫入、隊列與查詢需求決定;GraphDB 按實際多跳查詢需要評估。資料契約不依賴特定資料庫,但不承諾換資料庫只需改連線字串。

發布流程:固定輸入版本 → 產候選 → 驗證引用／計算／必讀紀錄 → 檢查相關依賴是否已更新 → 在同一檔案系統完成不可變 bundle → SQLite 交易登記發布與 latest 指標。若中途失敗,未登記包不可見並可恢復／清理;不能出現半張新卡。相關來源在分析期間更新,應重跑受影響層或明示發布為較舊快照且有待更新項,不得稱完整最新。

Git 用來審閱策略與研究內容版本,不代替執行期交易一致性。完整發布、來源和帳本的保存政策在首次運行前配置;引過的證據不因暫時不看該股而丟棄。無引用的重複快取可按保留政策清理。

## 六、事件與增量更新

2026-09-16 細化：補查分類、各層路由、反方退回、跨 packet 沿用證明及發布一致性，以 [補查與增量重評路由 v1](補查與增量重評路由-v1.md) 為實作規則正本；以下保留總體原則。路由設計已提交，不代表 SQLite 或自動沿用已完成。

只查「舊卡引用了什麼」會漏掉尚未引用的新文件。因此同時有實體／來源訂閱、新文件發現、依賴傳播、定期覆核和未知關係待查佇列。

| 變化 | 啟動與傳播 |
|---|---|
| 一般價格更新 | 程式更新 L5;重算 L4 現價折讓、反向要求、剩餘回報與 L6 計劃;未變逐字稿／財報不重讀 |
| 異常價格／量能 | 上述重算並開事件補查;沒查到原因就保留未知,不杜撰基本面變化 |
| 業績、指引、逐字稿 | L3 重讀新增原文及必要比較;重評 L4/L6,檢查 L2 假設與 L5 事件反應 |
| 產業／客戶／供應商報告 | 先更新相關主張與關係,找到訂閱和依賴公司;逐家算不同暴露,再到 L3/L4/L6 |
| 宏觀／政策 | 只沿有經濟機制的敏感度傳播,新關係進待查;不是所有股票同幅調整 |
| 來源更正／撤回 | 引用版本標記受影響,新發布重評;保留原引用與當時結論 |
| 驗證日／來源期限到期 | 檢查事件是否發生及來源是否仍適用;「沒消息」也可能影響論點 |
| 方法／研究委託改版 | 依變更範圍建立新研究任務,舊發布仍按舊方法評估 |
| 模型組合／模型委託變動 | 只觸發配置與風控,不將持倉成本／盈虧回流到研究 |

去重键使用事件／來源版本、受影響物件、方法版本;相同輸入重試不重复發布或記模擬成交。新事件在運行中到達可以合併待辦,但不能丟失依賴與截止時間。狀態至少區分 queued、running、succeeded、failed、superseded;失敗不能被無更新覆蓋。

## 七、模型組合與前瞻評估

P3 開始前,另版登記模型資本、基準、持倉與共同假設上限、壓力預算、現金處理、再平衡節奏、交易成本及可執行時點。研究頁先交付,不需等私人帳戶或正式注碼。

- 模型組合只消費已發布研究,並記錄為何選／不選、與其他股票／指數／現金相比的取捨。
- 模擬訂單須在發布之後,按預定的第一個合資格可成交時點處理。收市才確認的訊號不能成交在已過去的同一收市價;考慮交易日曆、盤前盤後、滑價、缺口及未成交。
- 日線同根同時碰目標與止損而不知道先後,按事先選定的保守慣例或標不可判;不能事後挑有利路徑。
- 原評級／期限／目標不可改寫;新目標新增 publication。撤回仍保留原紀錄,每次快照更新不重啟成功時計。
- 程式計算拆股、股息、費用、退市及現金後的總回報;LLM 解釋原假設與實際差異,不編造無紀錄的成交或動機。
- 股票評級按固定期限與預定比較口徑評估;模型組合與預先選定總回報基準同期間比較,分開選股、現金、行業集中及市場曝險的影響。
- 評分保留全部發布與候選去向,標識同一論點的相關版本,避免把選中的贏家或每日重複評級當大量獨立證據。

這是系統自己的紙上決策紀錄,不等於真實可實現回報或用戶實際帳戶。原84宗是資料／能力回歸,不和前瞻模型組合混算績效。

## 八、交付順序與驗收

P 編號是本設計的工作包,不是虛構已開 Kira 票。沿用 Epic「根基重整」與 D09／D10／D11／D12;P1 由現有 KARST-240 承接,後續按依賴開通用能力票,不逐股票開取證腳本票。

| 工作包 | 交付與依賴 | 可檢查的完成條件 |
|---|---|---|
| P1 通用獨立股票頁 | 首版來源／發布契約、最小索引、隔離上下文、通用取證、六層提示詞、估值／TA／計劃、HTML 一起完成 | 首頁可讀且數值／引用可核;不同生意第二股只換參數跑完整流程,再以同一批次入口驗首批名單;不讀帳戶 |
| P2 觀察名單與增量 | 依 P1;訂閱、任務、依賴、產業卡與每日 diff | 價格日只更新必要層;一份產業報告傳到至少兩家不同暴露公司;重試不重複發布;未知關係能列待查 |
| P3 模型組合與評估 | 依 P1 發布契約;可與 P2 部分並行,運行前固定模型委託 | 模型自行選／等／退出;帳本與研究隔離;發布後模擬成交;原目標不覆寫;能重算含成本的基準比較 |
| P4 擴大覆蓋與今日市場 | 依 P2;500+ 機械監測、產業候選與優先隊列、日報 | 批次與單股共用核心;日報只列值得處理的事件／條件變化,不是500份重複全文;記覆蓋缺口及任務預算 |
| W WeKnora 有界試用 | 與 P1/P2 並行;匯入申報、逐字稿、產業與用戶報告,接搜尋／原文工具 | 同一批研究任務比較檢索與引用品質、完成時間、模型／運維成本;實測修訂、撤回、同步及原文定位 |

P1 的最低資料骨架在交付股票頁時一起驗收,不獨立膨脹成先建完所有基建。第一頁是可直接使用的產品切片,第二股的目的在證明可重用,不是再做一個獨立研究項目。後續功能依真實運行痛點調整,不以新增學術考試阻塞。

WeKnora 不作證據或已發布判斷正本;其當前版本的授權、英語財務檢索、引用／修訂能力要實測,不把「50／200版」等未在本票核對的版本數字當永久事實。若節省的工作與品質增量成立即納入,不預先判定必留／必撤。圖譜與框架選型不阻塞 P1。

## 九、必要的實作驗收案例

以下是相應實作需要的行為驗收,不是本輪已運行的功能測試:

1. **輸入隔離**:把合成帳戶秘密放在禁止來源中,研究工具不能取用;隱藏帳戶變動不改傳給研究的輸入 digest。檢查提示與工具允許清單,不要求隨機 LLM 輸出逐字相同。
2. **估值／目標**:同一證據有今天的價值與指定日期目標;基準不等於區間中點。只變現價不應無故改經營情境,但折讓、隱含要求、R&R 必須重算。
3. **增量**:相同來源重抓沒有新來源版本;新逐字稿不因舊卡未引用它而漏掉;一個產業假設更新能找到不同暴露公司。
4. **時間**:歷史截止後實際值被拒、截止前未來指引可用;未確認 pivot 不能提前產訊號,未收週／月線為暫定。
5. **一致性**:發布前相關來源已改版時不能冒充完整最新;模擬中斷後沒有半張卡、重複發布或雙重成交。
6. **回顧**:修改現行目標仍可按舊目標日期評分;收市後發布不能回填同一收市成交;同根順序未知不選有利結果。
7. **通用性**:同一 CLI／核心函式單股與批次一致,公司差異由來源映射／資料配置處理;參數化 fixture 可有真實代號與預期值,不需要每股一支測試腳本。

改取證／抽取路徑时依 D-178 跑84包相關越界、錯位與引用檢查,原包及成績不改。當前僅修改設計文檔,不把未跑的回歸寫成通過。

## 十、實作約束與目前狀態

程式只進 karst/ 通用套件;模組職責見 [karst/README](../../karst/README.md)。代號、公司映射、日期、路徑、模型與來源配置為輸入;不建立 fetch_<ticker> 或一次性探索腳本。測試在 karst/tests/ 驗契約／失敗路徑,不測同一公式抄寫本。

本輪完成設計和規格對齊;取證器、角色 runner、HTML 股票頁、增量任務、模型帳本與 WeKnora 均需按工作包實作與驗收。不以本文中的擬定模組／路徑宣稱已存在功能。
