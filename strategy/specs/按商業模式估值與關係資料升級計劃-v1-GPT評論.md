## 1. 投資經理的估值方法

由經濟結構決定模型，由證據決定假設。每家公司先回答：誰付錢、收入如何形成、競爭優勢能維持多久、增長需要投入多少資金、最後多少回報屬於普通股股東。敘事必須落到需求、份額、價格、利潤、再投資、融資或存續機率之一；不能因「AI／能源／量子」標籤而改用更高估值公式。

共同經濟邏輯是未來屬於股東的回報，但實務的預測單位、估值方法、過渡期及風險處理不同。FCFF 是企業自由現金流的口徑，DCF 是折現方法；「五年 FCFF 加永久增長」只是其中一種實作。

| 經濟特徵 | 優先建模及主估值 | 交叉檢查與主要陷阱 |
|---|---|---|
| 成熟、盈利與再投資較可理解 | 正常化盈利／owner earnings、多階段 FCFF 或 FCFE | 盈利或現金流倍數；維持性資本開支、SBC 及營運資金不能免費 |
| 訂閱／軟件／平台 | 客戶、留存、客單價或交易量 × take rate，再推成熟利潤與再投資 | 前瞻盈利／FCF；EV/revenue 只在成熟利潤、留存及風險可比較時有意義 |
| 供需週期／製造／材料 | 量 × 價格、產能、利用率、單位成本、週期正常化盈利及現金流 | 中週期 EV/EBIT、P/E 或資產／重置成本；低谷與頂峰的當期 P/E 都會誤導 |
| 快速擴產／商業化轉正 | 訂單→交付→現金；建產、良率、客戶驗證、融資；多階段情境 DCF | 成熟狀態盈利或分部估值；預測期按生意何時成熟，不能機械固定五年 |
| 銀行／保險 | 股權現金流、可分派股息、超額收益；ROE、資本要求與信貸／承保品質 | P/B 必須連到可持續 ROE 與股權成本；不套一般工業企業 EV/EBITDA |
| 房地產／資源／資產型企業 | 資產或項目現金流、NAV，扣負債、開發／復原成本 | REIT 可用 AFFO，資源公司看價格週期；帳面資產不自動等於可變現價值 |
| 尚未形成穩定商業收入 | 里程碑／成功失敗情境、資金需求及稀釋；有適用條件才用風險調整 NPV／實質選擇權 | 不把 TAM 直接當收入，不把成功情境當基準；概率不可靠便展示条件與敏感度 |
| 多種經濟結構並存 | SOTP：各分部選適用方法，再合併總部成本、融資及權益橋接 | 分部交叉交易、共享成本、新業務選擇權不可重複計值 |

成熟增長要連到再投資與資本回報。穩態近似下，再投資率 = 增長率 / ROIC；營運增長並非免費。高增長且新投入資本回報低於資本成本，也可能損害價值。終值不能只把最後一期尚在擴張／異常的 FCFF 乘上永久增長。

每次研究保留三種答案：
1. **當日內在價值**：由獨立經營情境推導的範圍與基準，樂觀情境不是價值的數學上限。
2. **現價隱含要求**：固定哪些假設後，反推收入、利潤、超額回報年期或其他關鍵條件。反推不是唯一解。
3. **持有期價格情境**：例如六至十二個月後的盈利 × 有依據的倍數，或當時剩餘現金流價值；交代市場為何重估及催化劑。TA 目標另列，不用歷史高位冒充基本面估值。

最低要求是一個適用主模型及一個有計算支持的替代視角；兩者共享很多假設，不能視為兩票獨立證據，也不機械取平均。若無合適可比公司，替代可以是不同增長持續期／分部經濟／正常化盈利檢查，不強行湊倍數。分析員目標價與 Morningstar 要按日期、預測期間、GAAP/non-GAAP、股數、方法及關鍵假設拆解；不能只比較最終數字。

### 2.3 BE：核心問題是增長年期與競爭推論，並非證明 FCFF 無效

1. **不能由市價較高判定模型錯。** 保存的富途 Morningstar 回傳明列 fair_value = 97，報告更新日為 2026-07-29；Longbridge 機構平均目標為 280.23846，更新日 2026-09-14。兩者不是同一估值、日期或預測期限。未從 Morningstar 官網獨立取得更新版本；來源 meta 亦註明是 agent 從 MCP 回傳轉存，重新研究須核驗新資料。
2. **GAAP／non-GAAP 口徑錯要改，但改成 17% 長期 GAAP 利潤率是另一個投資假設。** 不能把會計標籤修正當成已證明穩態利潤上限。
3. **本公司的擴產成本低，不等於競爭者能低成本進入。** 覆核由 Fremont 投資及 CEO「擴產回本以月計」，推到有效供給迅速增加、均衡租金回吐。需要另外查技術、良率、可靠性、客戶認證、服務能力、競品交付與總成本。原文同樣可能支持 BE 的高增量資本回報；它本身不足以判定哪個方向勝出。
4. **2031 年是否已進穩態尚未建立。** 五年明確預測後直接轉 4–5% 永續增長，未清楚呈現短期缺電窗口、長期分散供電採用及競爭優勢各自能維持多久。延長預測期不是為了抬價；須同時延伸競爭、再投資與利潤回落。
5. **六個月價格目標的橋接不足。** 160／355 主要援引歷史供需區／高位，245 的下調理由是 DCF 差距更大。應保留其 TA 性質，另計預測期間明確的 EPS × 倍數或期末价值；不可只以 DCF 改變就任意移動倍數。
6. **資本結構需重查。** 目前因市价高於轉股價，把可轉債在所有低估值情境均視為股本。應按條款與各情境處理債券／轉股權，不能以當日價內推定永遠轉股。SBC 費用與未来發股亦需一套一致橋接，既不漏計也不雙扣。

重建 BE 的經營模型：交付 MW × 實現單價及產品成本；存量設備 × 服務附著／單位收入及服務毛利；新產能、營運資金、客戶融資／集中度；再做增長→過渡→成熟的現金流。若分部資料足夠，用設備與服務 SOTP 交叉檢查；分部服務現金流不能同時在設備估值重算一次。再以清楚年份及口徑的前瞻盈利／EBIT 倍數重建持有期價格情境。

### 2.4 AXTI：一項可重現算術錯誤及兩項結構問題

**確認的敏感度錯誤**：研究 top_assumptions 第三條及 alternative_view 說，改用 9% 折現率、3.5% 永續增長，再換樂觀現金流，價值約 55–60。對保存的輸入逐項重算：

- 樂觀現金流（百萬美元）：[15, -30, 60, 175, 260, 327]。
- 現金 748.848、負債 84.233、其他資產／請求權 0、股數 66.5 百萬。
- 沿用現行計算器六個逐年期末時點，r = 9%、g = 3.5%。
- 明確期現值 522.778065；終值現值 3669.158099。
- 每股 = (522.778065 + 3669.158099 + 748.848 - 84.233) / 66.5 = **73.0308446**。
- 同 r/g 下基準現金流得 **41.7709635**，與文中的約 41.8 一致；錯的是樂觀路徑的 55–60。
- 這是核算舊情境的文字錯誤，不是認可 9%／3.5%，不是新的 AXTI 目標價，也未修正下述時點及權益問題。

**現金流時點**：第一期寫 2026 下半年，程式卻折現一年，其後至 2031 各折現二至六年。需由 2026-09-16 估值日計剩餘現金流，排除已發生的半年部分，並明列期末或期中慣例；「保守」不是錯置日期的理由。

**少數股東**：用一季少數股東淨利佔比，把整段合併 FCFF 統一乘 0.86，再把合併現金／負債帶入。這未證明等於母公司股東可得價值。應按實際子公司／資產權益、可分配現金、贖回權及估值請求權處理；不能用當季利潤比代替所有年度的經濟權益。

重建 AXTI：產品／子公司能區分就分開；需求→客戶認證／許可→產能與良率→出貨／單價→毛利→擴產及營運資金→母公司股東價值。用正常化盈利或分部估值檢查，不因當期高 P/E／EV/EBITDA 就否定所有前瞻倍數方法。研究自身估算 2027 EPS 與 NTM 共識也不能直接視作同期間。

## 3. 股票—產業—報告的關係：SQLite 留在服務後面

目前 store 有 entities、sources、research_versions、jobs 與 evidence_text FTS5；entity tags／證據清單不等於經濟關係與推論依賴已完成。SQLite 不暴露給 ChatGPT 是正常封裝。兩端都由 MCP 語義工具讀寫，毋須直接 SQL 或開放 DB。

分清兩種圖：
- **價格圖**：日／週／月、200MA、支撐阻力及圖像保存，屬 KARST-246。
- **經濟關係圖**：公司、產品、價值鏈環節、共同假設與來源主張，連到研究層；是本提案的新交付。

建議最小資料模型（名稱可配合既有契約，勿另造平行來源庫）：
- entities：沿用現有穩定識別，擴展產品／行業／價值鏈節點。
- claims：可版本化主張，區分來源事實陳述、作者預測、管理層說法、本系統推論；記錄立場與狀態。
- relationships：from、predicate、to；例如 supplies_to、competes_with、depends_on、exposed_to。附機制、方向、適用期間、暴露大小／未知、相關 claim。
- claim_evidence：引用來源版本與 locator，一份報告可支持或反對多條主張，不重複保存全文。
- research_dependencies：哪一版研究、哪一層、哪個估值 driver 依賴哪個主張／關係版本。

公開／取得／記錄時間與經濟有效期間分清。來源更正或推翻保留舊版本；按截止日查詢必須同時避免讀到當時尚未記錄或不可取得的新主張。未知不寫成不存在。數值機率／暴露沒有依據就留空。

提議四個 MCP 工具能力（接口名稱待實作時定稿）：
1. `get_relationships(subject, relation_types, direction, depth, as_of)`：回傳有上限的節點／路徑、證據、版本、缺口；避免整個圖倒進 context。
2. `upsert_relationships(changes, evidence_refs, expected_versions)`：agent 可新增、修訂、標示推翻；來源有據與研究假說分明；衝突寫入不靜默覆蓋，不設逐條人工批准。
3. `link_evidence(evidence_id, entity_ids, claims)`：報告連到涉及的公司、產業與主張。共現公司名字不自動建立供應商關係。
4. `get_impacted_research(change_id, scope)`：列受影響股票／層／估值 driver 及傳播理由，供 agent 局部重評；不把圖上連通直接轉為負面／正面評級。

500 家不是必須 GraphDB 的門檻。先用 SQLite 的索引關係表及有界遞迴查詢；監測寫入併發、實際路徑查詢延遲與維護負擔。多人多服務寫入再評 PostgreSQL，複雜深層圖分析成為主要負載再評專用圖庫。這些引擎選擇不應改 MCP 契約。

關係圖直接服務估值：例如一份報告改變「數據中心某類電力需求」假說，先判哪些公司暴露，再辨別影響是銷量、單價、競爭年期或資本開支。BE 與 AXTI 可能有共同終端需求假說，但不能因此杜撰它們直接供應彼此。關係與影響強度都要查來源。

### 最小驗收

- AXTI 保存輸入 r=9%、g=3.5% 的敏感度確實產生 73.0308446；另有 stub period 的日期測試，不能用同一年度公式自證。
- 同一研究能保存主 DCF 與可計算的替代估值；收入／利潤／再投資改動能重算到每股結果。
- 現價反推顯示固定了哪些條件；樂觀標為「此情境」，不是「最高可能價值」。
- BE 兩套競爭假說均處理：優勢延續與供給正常化；不得把 incumbent 擴產 capex 等同競爭者進入門檻。
- 價格更新只改現價要求、TA、期限計劃等受影響項；基本面公允值不因價升自動上調。
- 一份報告修訂後只標記相關依賴；傳播回傳理由，不直接改股票評級。
- 可按舊截止日讀回當時的關係與研究；兩個客戶端均能查詢及有版本檢查地修訂同一關係。
- 所有實作通用、代號參數化；不提交股票專用腳本。只有變動取證／抽取路徑時才跑相關 84 包回歸，不把完整研究實驗當成產品上線前提。
