# strategy/tools —— 即時判斷用的小工具

這個目錄放**看一家公司當下值不值得研究下去**的計算工具。它不是策略引擎的一部分:不碰 `karst/`(D-165 引擎凍結),不做回測,不掃參數,不產生訊號。

目前只有一支:

## implied_expectations.py —— 隱含預期計算器(KARST-183)

### 它答什麼問題

不是「這家公司值多少」,而是**「現價要求公司做到什麼,才剛剛好對得住這個價」**。方向反過來:把股價當已知,把經營路徑當未知,解出未知那一項。

輸出兩件**分開**的東西,第二件不由第一件推導:

- **(甲)長期價值範圍**——在一組明寫的經營假設下,公司每股值多少。用現金流折現。
- **(乙)一年持有回報情境**——一年後市場若只給某個市銷率,持有一年的回報是多少。用公司自己過去幾年的市銷率分佈當退出倍數,**與(甲)的折現值無關**。

分開的理由:一年期限如果只是把十年折現值除以時間,那個期限根本沒有進入投資判斷。一年內能不能賺錢,靠的是市場肯給什麼倍數,不是靠內在價值最終會不會兌現。

### 用法

```
python strategy/tools/implied_expectations.py SNOW AXTI                 # 只印帳目與市場快照
python strategy/tools/implied_expectations.py SNOW AXTI --full          # 反推表 + 敏感度 + 兩個輸出
python strategy/tools/implied_expectations.py AXTI --full --base annualized_q --json out.json
python strategy/tools/implied_expectations.py SNOW --full --override-discount-rate 0.12   # 人手覆寫折現率,見下方「資本成本規則」
python strategy/tools/implied_expectations.py ON --full --credit-spread 0.015             # 換信用差價(預設 2.0 個百分點是示例值)
python strategy/tools/implied_expectations.py CLVT --full --de-cap 2.0                    # 換重槓桿的 D/E 上限(預設 3.0 倍)
python strategy/tools/implied_expectations.py SNOW --full --net-cash-include-investments  # 判「淨現金」時把短期及長期投資也當現金
```

`--base annualized_q` 把最近一季 ×4 當起步年,用於剛剛轉折、TTM 明顯落後的公司。

新增一家公司要在檔內 `CASES` 加一格固定假設(銷售資本比、正常化利潤率、一年情境的
收入增速格等——**不含折現率**,資本成本規則見下方「資本成本規則」一節,`--full` 批次跑
時全部公司共用同一組規則輸入、逐家算出自己的 WACC,不用逐家填)。這些是判斷,不是資料;
每次改動都要在結果檔的假設清單寫明理由。現時 `CASES` 有七家:SNOW、AXTI、LULU、
TDC、ON、ENPH、ARM(後四家的假設由 KARST-184 的
`research/2026-09-methodology/2026-09-08-①候選池走通/run_three_numbers.py` 原封搬入)。

### 三組假設(一組都不能省)

1. **經營路徑**——第一階段的收入年增率、這一階段維持幾年、之後的增長率、第 N 年的正常化營業利潤率、利潤率由今日走到目標要幾年。
2. **現金流轉換**——稅率;增長所需的再投資 = 收入增加額 ÷ 銷售資本比(增長不能免費,高增長必然吃現金);股權薪酬的處理。
3. **長期估值**——折現率、終值增長率、終值期投入資本回報率(決定終值再投資率)。每次輸出都印**終值佔企業價值的比重**。

### 兩個口徑,寫死在這裡

**股權薪酬與稀釋。** 股權薪酬在 GAAP 營業利潤裡**已經是費用**,計算器直接用 GAAP 營業利潤,**不加回**;股數用**稀釋後**股數。這一套在(甲)裡就是完整的處理——不再另外扣未來稀釋,否則同一件事扣兩次。(乙)那一邊因為要算一年後的每股價格,才另計一年淨稀釋,取「股權薪酬 ÷ 市值」(授出價值佔市值的比例約等於新增股數佔總股數的比例),下限 0.5%。兩家公司用同一套。

**企業價值轉每股價值。** 每股價值 =(企業價值 − 淨負債)÷ 稀釋後股數。
淨負債 = 有息負債 + 經營租賃負債 + 少數股東權益帳面值 − 現金 − 短期及長期投資。
少數股東權益放進淨負債那一邊,是因為企業價值屬於全體資本提供者,不只母公司股東。

### 資本成本規則(KARST-190 定折現率,KARST-193 改為 WACC 口徑,KARST-196 補槓桿調整)

`--full` 批次跑時,折現率不再逐家在 `CASES` 手填,改由規則自動算出,同一批候選公司
共用同一組**規則輸入**,再逐家算出自己的折現率。

**為什麼要改。** 這套模型折現的是**企業自由現金流**(FCFF——付利息之前的現金流),
折出來的是企業價值,之後再減淨負債得股權價值。FCFF 對應的是**全體資本提供者**要求的
回報,即加權資本成本(WACC);十年期美債 + 5% 那個數是**股東**要求的回報(股權成本)。
KARST-190 把股權成本直接套在 FCFF 上,等於用股東的必要回報去折一筆連債主那一份都
包含在內的現金流——有債的公司會被系統性低估。KARST-193 修正這一處。

**KARST-196 再修一次:股權成本要隨槓桿升。** KARST-193 那條規則的股權成本**不隨
槓桿變**,而稅後債務成本恆低於股權成本,於是**債務權重越高、WACC 越低**——方向與
公司金融的基本結論相反(加槓桿令股權風險上升,WACC 大致持平,只差稅盾)。實測
TROX / CLVT / LUMN / COLL 四家債務補上之後,WACC 由 10.0% 機械地跌到 6.0–7.0%,
估值因此被推高;而且規則本身**沒有下限**,一家槓桿高、又剛好過得到負債閘的公司,
會同時拿到便宜的折現率與通行證。改法見下面「重槓桿」兩行。

**公式:**

| 項 | 算法 |
|---|---|
| D/E | 有息負債帳面值 ÷ 市值(與下面權重同一口徑,含融資租賃);**截頂 3.0 倍** |
| 重槓桿後股權溢價 | 無槓桿溢價 5.0 個百分點 × (1 + (1 − 稅率) × D/E) ← **Hamada 重槓桿** |
| 股權成本 Ke | 十年期美債收益率 + **重槓桿後**股權溢價(**四捨五入前的原值**) |
| 稅前債務成本 | 十年期美債收益率 + 信用差價(第一版全批固定 **2.0 個百分點**) |
| 稅後債務成本 Kd | 稅前債務成本 × (1 − 稅率),稅率取 `CASES` 那一格 |
| 權重 | 股權 = 現價 × 稀釋後股數(市值);債務 = **有息負債帳面值** |
| WACC | max(Ke × 股權權重 + Kd × 債務權重, **規則下限**),**四捨五入至最近 0.5% 在這一層做** |

**出處與理由。** 重槓桿式出自 Hamada (1972):βL = βU × (1 + (1 − t) × D/E)。
股權成本若寫成「無風險利率 + β × 市場溢價」,溢價就隨 β 同比例放大,所以
「5.0 個百分點」由**固定溢價**改讀成**無槓桿(零負債)股權溢價**,有槓桿的公司按
自己的 D/E 放大。這樣改之後,WACC 對槓桿仍然會跌,但只跌一個**稅盾的幅度**——
代入之後有一條封閉式(w = 債務權重、Ke_u = 無槓桿股權成本、s = 信用差價):

```
WACC(w) = Ke_u − w × [ 稅率 × Ke_u − (1 − 稅率) × s ]
```

今日參數(美債 4.806%、無槓桿溢價 5.0pp、差價 2.0pp、稅率 23%)下,斜率只有
**0.714 個百分點**:由零負債走到全債務,WACC 只由 9.806% 跌到 9.088%。舊規則同一段
跌到 5.65%。**這就是「槓桿升,WACC 大致持平,只差稅盾」那句話的算式形態。**

**下限不是外加的任意數字,是同一條公式的極限值。** 上式是線性,極小值必在
w = 0(= Ke_u)或 w = 1(= (1 − 稅率) × (Ke_u + 差價))其中一端,取細那個即
`wacc_floor`。它只在 D/E 被截頂、算出來的 WACC 越過這條線時生效(六十家之中只有
TROX、CLVT),生效時 `wacc_floor_binding` = True 並印警告。寫成「兩端取細」而不是
寫死一條式,是為了差價大到蓋過稅盾(斜率反號)時,下限會自動變回 w = 0 那一端,
不會反過來抬高零槓桿公司的折現率。

**D/E 截頂 3.0 倍(`DE_CAP`,可用 `--de-cap` 改)。** 重槓桿後溢價對 D/E 線性,
D/E 爆大時溢價會爆到二十幾個百分點(TROX D/E 4.21 → 溢價 16.55 個百分點、股權成本
21.36%),那個股權成本已經沒有意義——這種公司的股權其實是一張期權,不是單一折現率
描述得了的東西。截頂會在 `notes` 與 `_meta` 的 `warnings` 印一句、`de_capped` = True。
**截頂只壓住報出來的股權成本,WACC 那一邊由下限兜住**,兩者合起來令 WACC 對任何
槓桿都落在 [wacc_floor, Ke_u] 之內——這就是「不會同時拿到便宜折現率與通行證」。

**一處誠實的近似:債務 beta 當 0。** 那是 Hamada 的教科書前提(債務無風險),但這裡
的債務成本帶 2.0 個百分點信用差價,兩者不完全一致。方向是**保守**的:債務 beta 若
大於 0,股權 beta 應該升少一點、WACC 應該再低一點,所以本規則給出的 WACC 只會偏高、
不會偏低。稅率與差價同時為 0 時,WACC 對槓桿完全水平,回到 MM 的結論(已自檢)。

**淨現金公司(有息負債 ≤ 現金)** 沒有實質槓桿,D/E 當 0、溢價維持無槓桿值,
WACC 直接等於股權成本,輸出印一句說明,數字與 KARST-190 / 193 完全相同。這條「淨現金」的判定對齊 D-162 釘死的 N2 口徑
(現金 − 總債務);要把短期及長期投資也算進現金那一邊,加 `--net-cash-include-investments`
——SNOW、ENPH 這種「現金少於有息負債、但現金加證券遠多於有息負債」的公司會因此翻邊,
翻邊之後 WACC 變回股權成本、每股值退回舊值。**這一格是判斷,不是事實**,見限制第 12 條。

**信用差價 2.0 個百分點是示例值,待對齊。** 它不是任何一家公司的信用評級推算,是為了
把口徑先修正好而放的一個佔位數。要換就用 `--credit-spread`。差價每加 1 個百分點,
有債公司的 WACC 只升 (1 − 稅率) × 債務權重 個百分點——ON 那種 13% 債務權重的公司
約 0.10 個百分點,影響遠小於股權溢價那一格。

輸出 JSON 的 `_meta.cost_of_capital[代號]` 記齊:股權成本、稅前 / 稅後債務成本、
市值、有息負債帳面值、兩個權重、未四捨五入的 WACC、四捨五入後的 WACC、是否淨現金;
KARST-196 另加(**只加欄不刪欄**)`relever`(走哪一套重槓桿,`hamada` / `none`)、
`equity_premium_unlevered`(無槓桿溢價)、`equity_premium_levered`(重槓桿後溢價)、
`cost_of_equity_unlevered`、`de_ratio`(原值)、`de_ratio_used`(截頂後)、`de_cap`、
`de_capped`、`wacc_floor`、`wacc_pre_floor`(未套下限前)、`wacc_floor_binding`、
`warnings`(截頂與下限各一句)。`_meta.discount_rate` 那一格同時多了
`equity_premium_unlevered`、`cost_of_equity_unlevered`、`de_cap`、`relever`。
`_meta.rate_path[代號]` 記這一家走了下面四條路的哪一條。

十年期美債收益率:FRED 的 `DGS10` 系列與 yfinance 的 `^TNX` 兩個來源都試,取日期較新
的那筆(FRED 常常慢幾日才更新收市值,`^TNX` 是即市代碼,新鮮度更可靠)。兩個來源
各自的嘗試結果連同取數日期一併寫進輸出 JSON 的 `_meta.discount_rate` 頭部,供事後
查來源。兩個來源都失敗就直接報錯,不會靜默套一個假數字——折現率是全套裡最強的
槓桿(見下方敏感度表)。

`CASES` 裡舊留下的 `wacc` 欄(SNOW 的 10%、AXTI 的 12% 就是舊「逐家手填」做法的
產物)現在只當歷史記錄,計算時一律忽略並在輸出印警告。要用人手指定的折現率,必須
在命令列明確加 `--override-discount-rate 0.12` 這樣的旗標(小數,整批共用同一個
值),輸出會標明「手動覆寫」——不會再靜默從 `CASES` 讀到一個沒人記得是哪來的數字。

敏感度:除了原有全項目 ±10%(相對)的敏感度表,折現率另外自動多印 ±1 個百分點
(絕對值)兩組基準情境每股值,直接答「差一個百分點,結論差多少」。

代價:5.0 個百分點的股權溢價本身仍是判斷,不是市場觀察——換一個溢價假設,折現率
跟著換。這條規則解決的是「用什麼利率」這一步從逐家手填改成有紀律、可重現的公式,
沒有解決「這個公式對不對」這個更深的問題,見下面限制第 4 條。

**四捨五入到 0.5% 這一步本身會製造跳級。** WACC 只要跨過 0.25% 的界,折現率就跳
半個百分點,而長期價值對折現率極度敏感。SNOW 就是例子:它的 WACC 未四捨五入是
9.715%、股權成本 9.802%,兩者只差 0.09 個百分點(每股 +0.91),但一個落在 9.5%、
一個落在 10.0%,四捨五入額外再送 +4.31——**七成以上的價值變動來自取整,不是來自
槓桿**。讀前後差異表時要連同拆解一起讀,見更正紀錄那張表。

**折現率的四條路(由上而下,先中先用),`analyse()` 的舊呼叫方式一句沒改;
走了哪一條記在回傳的 `rate_path` 與 `_meta.rate_path[代號]`:**

1. `--override-discount-rate`(`manual_override=True`)——直接用傳入值,全批共用,不算 WACC。(`manual_override`)
2. `rate_inputs=`(KARST-193 新增,`--full` 預設走這條)——逐家算 WACC,KARST-196 起
   股權溢價按 D/E 重槓桿。(`rule_wacc`)
3. `discount_rate=`(KARST-190 的批次規則值)——全批共用這個數,不算 WACC。舊腳本傳這個參數,行為完全不變。(`batch_discount_rate`)
4. 兩個都不傳,直接呼叫 `analyse()`(不經 CLI,例如 KARST-184/186 的舊重跑腳本)——沿用
   `CASES` 內的舊手填值,行為不變。(`cases_legacy`)

只有第 2 條會算 WACC,所以只有第 2 條受 KARST-196 影響;另外三條的 `wacc_detail`
一律是 `None`,四條路的實跑對照見更正紀錄。`cost_of_capital(..., relever=False)`
可以原樣重現 KARST-193 的舊算法,**那是給前後對照與回歸測試用的**,不是正常路徑。

### 聯合情境(KARST-193)

原有的敏感度表逐項各改 ±10%,答的是「這一項錯一成,結論偏多少」。但假設不會各自
獨立出錯:增長不如預期的公司,利潤率多數同時不如預期,而市場對它要求的回報同時上升。
所以另外印三組**聯合情境**——三項一齊偏向同一邊:

| 情境 | 第一階段增長 | 目標營業利潤率 | 折現率 |
|---|---|---|---|
| 悲觀 | −10 個百分點 | −5 個百分點 | +1 個百分點 |
| 中性 | 基準 | 基準 | 基準 |
| 樂觀 | +10 個百分點 | +5 個百分點 | −1 個百分點 |

輸出每股值、相對現價的幅度、終值佔比。這三個數之間的**距離**才是真正的下行空間;
逐項 ±10% 那張表會令人低估一齊出錯的情形。注意這裡與(甲)原有的悲觀 / 基準 / 樂觀
三格**不是同一組**——原有那三格另外還改了恢復期增長與終值增長率,幅度也不同,兩張表
並存,不刪。

### 一年回報表:四情境,固定次序(KARST-193)

一年那一邊改為固定四行、固定次序,**「倍數不變」永遠第一**:

| # | 情境 | 收入路徑 | 退出倍數 |
|---|---|---|---|
| 1 | 經營按基準路徑、倍數不變 | 基準格 | 現時市銷率 |
| 2 | 經營改善、倍數收縮 | 樂觀格 | 近一年 25 分位 |
| 3 | 具體反證出現、倍數回到常態 | 基準格 | 近一年中位 |
| 4 | 論點失效 | 悲觀格 | 近一年 25 分位 |

收入格取自 `CASES` 的 `g1_cases`:三格按增速排序,最低 = 悲觀、最高 = 樂觀、中間 = 基準。
退出倍數用**近一年**分位(近一年才是同一盤生意的定價區間);近一年樣本不足才退回四年
分位並在輸出說明。原有那張「收入格 × 歷史市銷率格」的網格保留為附錄,一行沒刪。

**次序本身是紀律。** 第一行先答「市場什麼都不改變主意,單靠經營一年賺不賺得到錢」——
這一行不需要任何重估理由,因為它沒有假設任何重估。之後三行每一行都在動倍數,而動倍數
就是在假設市場改變看法。

**規則:倍數變化必須接到盈利能力 / 增長 / 風險 / 資本配置的一項具體變化。** 情境 2、
3、4 各有一個**「重估理由」欄,由使用者填**(`RERATING_REASONS[代號] = {2: "...", ...}`,
或呼叫 `analyse(..., rerating_reasons={...})`)。空白時輸出印警告但**不阻止跑**——
寫不出那句話,那一行就只是把倍數當自變數亂撥,回報數字看似精確,其實沒有內容。
情境 1 自動填「不適用(倍數不變)」。

另有一個自動警告:現價市銷率已經**低於**近一年 25 分位時(LULU 2026-09-08 就是),
情境 2 與 4 的「倍數收縮至 25 分位」實際上是倍數**上調**,那兩行會變成正回報,名不副實
——這時要把名字反過來讀,或者自行改用更低的退出倍數。

### 資產負債表取數規則(KARST-195 統一修八處缺陷)

KARST-188 用這支工具跑六十家候選池,由寫卡片的人對著一手 10-Q 逐行核帳,查出取數層
有**六處缺陷,每一處都已經改變過結論**;本票另加第七處(收市價核對),修完重跑六十家
時再查出第八處(含糊標籤)。八處全部在本票修好,一手證據見
`research/2026-09-methodology/2026-09-09-①候選池全量/`。要點:**沒有一處是工具自己
捉到的**——輸出照樣印得整整齊齊,錯處只有對一次一手報表、或者對一次重跑差異才看得見。

| # | 缺陷 | 修法 | 最極端的實例 |
|---|---|---|---|
| 一 | 稀釋股數被當成流量、用 `quarterize()` 拆季 | 不拆季,直接取未拆季 duration 事實中結束日最近的一筆(同一結束日優先取季度期);再與 yfinance 現時股數對照,差 >±25% 改用市場股數 | ORCL 股數讀成 **0**(除零報錯);FN 讀成真實值的 0.1%,基準每股值變成現價的 +99,660% |
| 二 | 債務標籤清單太窄,取不到值就當「沒有負債」 | 三桶:合計標籤 / 流動分項 / 非流動分項,加入信貸額度、可轉債、有抵押債、其他短期借款、`*AndCapitalLeaseObligations*` 一系;分項再拆成互不重疊的「族」,族之間相加、族之內只取一條 | ORCL 的 1,295 億債務讀成 **72 億**;CLVT 的 43 億債務全部漏掉,淨負債由 +41 億變成**淨現金 −1.9 億** |

| 四 | 合計標籤同時進流動與非流動兩個桶 | 合計標籤只准住 `INV_AGG` 一格,與分項**取較大者、永不相加**;另加保險絲:流動桶與非流動桶金額完全相同即判為同一筆,不重覆計 | RMBS 同一筆 6.518 億證券計兩次,淨現金虛報 6.518 億 |
| 五 | 融資租賃整筆漏計 | `FinanceLeaseLiability*` / `CapitalLeaseObligations*`(流動 + 非流動,或合計)**計入有息負債**;經營租賃照舊分開放 `lease_debt` | 全批 29/60 家、合共 97.1 億美元;**DOCN 的負債閘因此判錯**(淨負債 6.331 億 → 10.429 億,由「過」變「不過」) |
| 六 | companyfacts 會靜靜地落後一季 | 對 EDGAR 申報清單交叉核對,落後就**拒絕給基準值** | RMBS、CLVT 等 5 家的資產負債表停在 2026-03-31,而公司早已申報 2026-06-30 那一季 |
| 七 | 把交易時段的即市報價當成收市價 | 按**美東時間**判交易時段,未收市就退回上一交易日 | 同一日相隔一小時抽兩次,六十家之中五十九家價格不同;STRL 只需 +0.13% 就跨過回報底線、擠走 LINC |
| 八 | `LongTermDebt` / `NotesPayable` 被一律當成「總額」,但一半申報人用它報**非流動那一行** | 逐家用申報歷史判它是總額還是非流動;判為非流動就進非流動桶,流動部分照樣另外加 | QCOM 的 152.70 億債務讀成 **127.81 億**(流動的 24.89 億整筆漏掉,低估 16%);ON 漏 8.02 億 |

**每次輸出都印出每家用了哪個標籤。** `fin.notes` 內有一句「取數標籤:……」,JSON 的
`_meta.extraction[代號]` 記齊逐格的標籤名、結算日與金額。這一步不是裝飾——上面六處
缺陷全部屬於「取到了一個數,只是取錯格」,不印標籤就查不出來。

**合計標籤 vs 分項標籤,規則寫死:取較大者,永不相加。** 合計標籤本身已包含全部;
分項標籤族之間互不重疊,可以相加。桶值 = max(合計標籤, 各族最大值之和)。合計標籤
在同一組內**先比新鮮度、後比金額**,而且合計標籤的結算日早於分項桶就棄用(反過來
先取金額最大,會挑中上一季的舊總額,再被新鮮度規則整筆丟掉,債務當零——CLVT 與
TROX 一度因此變成淨現金公司)。

**債務附註的本金總額不當帳面值用。** `DebtInstrumentCarryingAmount` /
`DebtInstrumentFaceAmount` 這兩格報的是**本金**,不是資產負債表帳面值(帳面值 =
本金 − 未攤銷折價與發行成本)。本工具只在資產負債表口徑完全取不到值時才退到這一格,
並印警告。差別實測:ORCL 本金 1,301.05 億 vs 帳面 1,295.41 億(差 5.64 億,0.4%);
CRNC 本金 1.80 億 vs 10-Q 帳面 1.7346 億(差 3.8%)。**兩家之中只有帳面值對得上
一手 10-Q**,所以取帳面值。

**含糊標籤逐家判,不靠定義。** `LongTermDebt` 與 `NotesPayable` 兩條標籤,**不同申報人
用法相反**:有人用來報「全部有息負債的總額」,有人用來報「資產負債表上非流動那一行」。
US-GAAP 的元素定義本身解決不了這件事(定義讀落像總額,但大量申報人當非流動那一行用)。
`classify_ambiguous_debt_tag()` 的做法是**在該公司的申報歷史裡找證據**:由新到舊找一個
「該標籤與非流動標籤同日並存」的結算日,比對

- 標籤值 ≈ 非流動值 → 它是非流動那一行,歸入非流動桶,**流動部分照樣另外加**
- 標籤值 ≈ 非流動值 + 流動值 → 它是總額,歸入總額桶

容差 1%。兩者都對不上就繼續向前找;全無證據就當總額(沿用舊行為)並**印警告**,那一家
要人手核。實測六十家之中 19 家用這兩條標籤,全部判得出,沒有一家落入「無證據」。
判斷結果記在 `_meta.extraction[代號]["debt"]["ambiguous_tags"]`。

實例:QCOM 在 2025-09-28 的 `LongTermDebt` 與 `LongTermDebtNoncurrent` 同為 148.11 億,
所以它是非流動那一行;2026-06-28 取數時,`LongTermDebt` 127.81 億再加 `DebtCurrent`
24.89 億 = 152.70 億。當成總額就會低估 16%。

另外 `LongTermDebtAndCapitalLeaseObligations` 按 US-GAAP 定義**就是非流動那一行**
(含流動到期部分的是 `...IncludingCurrentMaturities` 另一條),所以寫死在非流動桶,
不進總額桶——放錯桶會令 LMB、GNRC、SAIA、DRS 漏掉流動到期部分。

**融資租賃有一種重覆計數的可能,工具只警告、不靜靜調整。** `*AndCapitalLeaseObligations*`
一族的合計標籤按定義已含資本(融資)租賃,再加一次融資租賃就是計兩次。實測 CLVT
是這一格(重覆 2,760 萬,佔淨負債 0.7%)。工具在 `notes` 印一句明示,不自動扣減——
靜靜扣掉會令「這個數怎樣來」更難查,而金額多數細到不影響結論。**這一條要人手判。**

### 報表新鮮度核對(KARST-195 第六項)

`filing_freshness()` 由 `data/sec/submissions/CIK##########.json`(本地快取)取該公司
最近一份 10-Q / 10-K 的**申報日與所涵蓋期末日**;本地快取自己比 companyfacts 還舊時,
即時打一次 `data.sec.gov` 端點確認——一份過期的對照表只會給出假的安心。

- **companyfacts 最新資產負債表期末日 < 最近一份 10-Q/10-K 所涵蓋期末** → 標「資料落後」,
  **輸出拒絕給基準每股值**:`valA` 各情境的 `per_share` 與 `upside` 置 `None`,原值移到
  `per_share_withheld` / `upside_withheld`,並加 `withheld: True`(**欄位一格不刪**),
  頂層另有 `baseline_withheld: True`。命令列印「【拒絕輸出基準值】」。
- **結算日距價格日超過 200 日** → 標「過期」並印警告(不拒絕輸出——它可能只是這家公司
  的財政年度剛好如此)。
- 要照樣看數字:加 `--allow-stale`(或 `analyse(..., allow_stale=True)`)。用了就要自行
  承擔口徑落後一季;`_meta.allow_stale` 與 `_meta.data_freshness[代號]` 會留下記錄。

**為什麼要拒絕而不是只印警告。** 這一格出錯**不會報錯**:表照樣填得滿,淨負債、現金、
股數靜靜地全部落後一季,除非逐家對 EDGAR 申報清單,否則查不出來(A-055)。一個會被
略過的警告,等於沒有警告。

### 收市價核對(KARST-195 第七項)

`market_data()` 按**美東時間**判市場狀態(週末與 16:00 之後 = `closed`;09:30 之前 =
`pre`;其餘 = `open`)。最後一根日線的日期等於美東今日、而當刻是 `open` 或 `pre` 時,
那一根是**未完成的當日線**,丟棄,退回上一個已完成的交易日。

- `mkt.price_check` 記齊:當刻美東時間、市場狀態、原本最後一根日線的日期、有沒有退回、
  最終價格日與價格;`_meta.price_check[代號]` 同步寫入輸出 JSON。
- 另有一條**成交量完整度**的警告(最後一根的成交量低於近 20 日中位的一半就提示可能
  仍未足全日)——只警告,不改價:時鐘才是判準,成交量只是旁證。
- 假期不另設日曆:假期當日 yfinance 根本沒有那一根,退回上一根本身就是退回上一個真
  交易日(實測 2026-09-08 交易時段注入 → 退回 **2026-09-04**,自動跳過 09-07 勞動節)。
- 測試可用 `market_data(fin, now_et=...)` / `analyse(..., now_et=...)` 注入時點。

**寧可用兩日前的真收市價,不要用今日的假收市價。** 問題不在誤差大小,在於這套流程把
一串門檻式的是非題(過線 / 不過線、過一把尺 / 過兩把尺)架在一個雜訊級數的輸入之上,
於是雜訊被放大成分類答案,而輸出表面上完全看不出來(A-056)。

### 淨負債取數規則(KARST-186 釘死)

**現金與投資:有序後備清單,不是「第一個有資料就用」。** 公司會換 XBRL 標籤(例如
lululemon 的 `CashAndCashEquivalentsAtCarryingValue` 停在 2019 財年,之後改用
`CashCashEquivalentsRestrictedCashAndRestrictedCashEquivalents`)。取數依序試每個候選標籤,
取**第一個覆蓋到最近一季(asof)前後 200 日內**的標籤,不是第一個「曾經有資料」的標籤——
舊寫法卡在舊標籤的過期資料上,現金被容差濾成 0,曾令 lululemon 淨負債誇大 15.15 億美元
(A-048,已修)。若全部候選標籤都缺近期資料,退回「合併全部標籤取最後一筆」的盡力結果,
並在輸出印 `[注意]` 警告——不再靜默當 0。完全沒有標籤資料(多數代表公司真的沒有這一項,
例如沒有租賃負債)不印警告,以免洗版。

**LongTermInvestments 要不要計入淨現金,不能只憑標籤名字放行。** 這一格理論上該放
可變現的證券(國債、公司債、存款證),但有重資產或合營/聯營的公司,個別申報也可能把
非證券的策略性股權投資塞進同一格。判斷規則:格內金額出現大幅跳動,或者公司本身有已知的
合營/聯營持股時,要讀最近一期 10-Q/10-K 的投資附註(Investments / Fair Value Measurements
那一節),核金額組成——是市場可交易的證券就計入淨現金,是策略性股權投資(通常另外報在
「Other assets」或用權益法核算的附註)就不計入。核過的例子:AXTI 的 LongTermInvestments
在 2026-06-30 跳到 2.986 億美元,10-Q Note 2 核實全部是國債、公司債、存款證;AXTI 對原材料
公司的股權投資(1,410 萬)另外報在 Other assets,不在這一格內(A-047,已核實成立,見假設冊)。
本規則只在 AXTI 這一個樣本驗證過,不代表全部公司都乾淨——大額波動的長期投資格仍應逐家核附註。

### 限制(先看清楚再用結果)

1. **沒有共識預估。** 手上只有申報帳目,沒有分析員的收入與盈利預測。所以「市場預期」一詞在這裡只能解作「用這套假設反推出來的數字」,不是任何人真的講過的預測。換一組固定假設,反推值就變。
2. **反推值不是唯一解。** 現價一條方程,未知數十幾個。工具做的是固定其餘、解出一項;每張表都要連同它固定了什麼一起讀。單獨一個數字沒有意義。
3. **敏感度只做 ±10%。** 只答「這個假設錯一成,結論偏多少」,不答「這個假設會不會錯」。
4. **折現率是輸入,不是市場觀察。** 折現率是全套裡最強的槓桿(見結果檔的敏感度表)。KARST-190 後改由規則自動算,KARST-193 再改為逐家 WACC,KARST-196 再令股權溢價隨槓桿升(見上方「資本成本規則」),不再逐家手填,但規則本身那條 5% **無槓桿**股權溢價仍是判斷——不是任何人觀察到的市場數字。重槓桿只是把這個判斷按槓桿放大,放大不會令它變成觀察。任何「貴 / 平」的結論最終都建基於這個假設出來的溢價。
5. **終值佔比往往超過 100%。** 明確預測期現金流為負(仍在燒錢或大量再投資)時,終值會超過企業價值全部。這不是錯,但代表結論幾乎全部押在十年後那一個假設上。終值佔比越高,結論越不可靠。
6. **線性利潤率爬升是簡化。** 由今日利潤率直線走到目標利潤率,現實不是這樣。虧損公司在早年不給稅盾,也不計淨營業虧損結轉的未來稅務利益——會低估。
7. **收入是唯一驅動。** 沒有分部拆解、沒有毛利率與經營開支分開建模、沒有營運資金。
8. **XBRL 標籤覆蓋不齊。** 缺股權薪酬標籤的公司會當 0 處理(會高估自由現金流),缺標籤時腳本會在輸出印 `[注意]`。長期投資一格用的是資產負債表標籤,可能混入非流動的非證券投資——要逐家核。
9. **一年情境用歷史市銷率當退出倍數。** 生意性質剛剛改變的公司(例如產品組合換代),歷史倍數的參考價值很低。腳本因此同時印近一年與四年兩套分位數,並按現價站在區間哪一邊自動換情境標籤。
10. **信用差價是佔位數。** 全批固定 2.0 個百分點,不是任何一家公司的信用評級推算。要換用 `--credit-spread`。它對結論的影響遠小於股權溢價那一格(見上方「資本成本規則」),但它仍然是一個沒有人核過的數。
11. **經營租賃負債不入 WACC 權重。** 權重只用有息負債帳面值;租賃負債照舊留在淨負債裡(減股權價值),但不當債務資本去攤薄折現率。lululemon 這種零有息負債、21.41 億租賃負債的零售商因此被判為淨現金公司、WACC = 股權成本。租賃債務化之後應否進權重是另一個議題,本工具未做。
12. **「淨現金」的判定會左右答案。** 預設只看現金(對齊 D-162 的 N2 口徑)。SNOW(現金 20.85 億 < 有息負債 22.82 億,但現金加證券 43.88 億)與 ENPH(4.98 億 < 5.73 億,加證券 9.31 億)兩家,換成 `--net-cash-include-investments` 就會由「有槓桿」翻成「淨現金」,每股值退回舊值。同一家公司、同一日,兩個口徑答案不同——用哪一個要自己講得出理由。
13. **四捨五入到 0.5% 會製造跳級。** WACC 跨過 0.25% 的界就跳半個百分點,價值跟著跳。SNOW 的價值變動七成以上來自這一步取整,不是來自槓桿(見更正紀錄的拆解欄)。
14. **資料源本身會落後,而落後看不出來。** companyfacts 收錄新一季有時滯後約一季(實測 60 家有 5 家、全部剛好落後 91 日)。工具現在會對 EDGAR 申報清單交叉核對並拒絕給基準值,但**拒絕的門檻只認「有沒有更新的申報」,不認「這一季的數字有沒有大變」**——沒被標落後的公司,不等於它的資產負債表就一定貼近今日。
15. **本金 ≠ 帳面值,而工具在退無可退時會用本金。** 資產負債表口徑完全取不到值時才退到債務附註的本金總額,並印警告。本金不扣未攤銷折價與發行成本,會高估(ORCL 差 0.4%、CRNC 差 3.8%)。見到這個警告就要人手核。
16. **含糊標籤靠申報歷史判,不是靠定義。** `LongTermDebt` / `NotesPayable` 的歸屬由該公司自己的歷史推出;歷史裡從未與非流動標籤同日並存的公司,工具會當它是總額並印警告,**那一家的流動到期部分有機會漏計**。六十家實測全部判得出,但這不保證下一家可以。
17. **經營租賃仍然計入淨負債。** 沿用 KARST-186 口徑:`net_debt` = 有息負債(已含融資租賃)+ 經營租賃負債 + 少數股東權益 − 現金 − 投資。融資租賃是本票新加進有息負債的;經營租賃一直都在淨負債裡,只是分開放在 `lease_debt`。要不要把經營租賃剔出淨負債是另一個未答的議題。
18. **重槓桿式把債務 beta 當 0。** 那是 Hamada 的教科書前提(債務無風險),但本工具的債務成本帶 2.0 個百分點信用差價,兩者不完全一致。方向是保守的——債務 beta 若大於 0,股權 beta 應該升少一點、WACC 應該再低一點,所以本規則給出的 WACC 只會偏高不會偏低。要更準就要逐家估債務 beta,那需要信用評級,現時沒有。
19. **D/E 上限 3.0 倍是判斷,不是市場觀察。** 3.0 倍 = 債務佔資本 75%,非金融公司到這一級已經是信貸故事;超過就截頂並印警告。六十家實測只有 TROX(4.21)、CLVT(3.58)碰到,而且兩家都被 WACC 下限兜住,改成 2.0 或 4.0 都不會改變它們的結論——但下一批候選未必如此。用 `--de-cap` 可改。
20. **折現率處理不了違約風險本身。** D/E 三倍以上的公司,真正的問題不是折現率高低,是股權可能歸零;單一折現率的現金流折現對它們本來就不合用。工具會印截頂警告,但**不會拒絕輸出**——見到那句警告,那一家要當信貸個案人手看,不是當估值個案。
