# KARST-156 判準(跑數前凍結)

本檔在**接觸任何回報數字之前**獨立 commit。之後一字不改。腳本與本檔不符,以本檔為準,
腳本要改。本票不產生「及格」,只產生**存在 / 不存在 / 量不出**三種判詞之一。

要答的問題:股數按年收縮(回購淨額大於發行)的公司,其後回報是否高過股數膨脹的公司?

## 一、宇宙與期間

- 池:KARST-146 帳目面板 718 家 × 免費行情源有價的 584 個代號,交集 **547 家**。
- 每月合資格 = 該月底 `in_index` 為真(當時是標普 500 成分)、有價、訊號非缺值。
  每月人數中位約 375。
- 訊號月:**2010-04-30 至 2026-07-31**。起點是面板 2009-04-30 加十二個月;
  終點是最後一個有完整下一月回報的月份(日線到 2026-09-01)。
- 分兩段另報:**2010-04 至 2016-12**、**2017-01 至 2026-07**。

## 二、兩版訊號(事先寫死,不得事後改)

兩版都定義為:

> **shrink = −(股數(t) ÷ 股數(t−12 個月) − 1)**
>
> 即股數跌 10% → shrink = +0.10。**數值愈大 = 收縮愈多 = 假設中愈好。**
> 排名相關度的預期正負號因此是**正**。

- **A 版**:面板 `diluted_shares`(攤薄加權平均股數),知情時點照 RULES.md
  (`filed` ≤ 月底、首版優先)。
- **B 版**:companyfacts 原檔的 `dei:EntityCommonStockSharesOutstanding`
  (封面頁實際在外股數,存量),原檔只讀
  `experiments/2026-09-02-fundamentals-panel/data/secfacts/`(D-134:不另存副本)。
  知情時點自行套用同一條規則:在 `filed` ≤ 月底的紀錄中取 `end` 最近者;同 `end` 取
  `filed` 最早者(首版優先)。只收 `shares` 單位、表格 `10-K/10-Q/20-F/40-F`
  (含 `/A`,但 `/A` 只可作修訂版,不得成為首版)。
- 兩版分開報全部結果。合併判詞以 A 版為主、B 版作佐證。

## 三、股數基準對齊與拆股剔除(死線)

D-125 的教訓:面板股數是**申報當時**的股數,日線價格**已調整拆股**;兩邊基準不對齊,
一次拆股就會在股數序列上造出一個假的「膨脹 400%」,或在市值上造出假的便宜。
所以本票的次序是:**先對齊基準,再剔除,最後才算變化率。**

### 3.1 對齊(第一步)

`shares_adj = 申報值 × Π(申報日之後所有拆股事件的比率)`

拆股事件表用倉內既有快取
`experiments/2026-09-02-fourpiece-test/data/splits.parquet`
(KARST-148 由 defeatbeta `stock_split_events` 取得,1,001 宗、384 個代號,
1994-07 至 2026-08),**只讀,不另存副本**。對齊之後,同一家公司整條股數序列
落在同一個(今日的)基準上,拆股本身不再在序列上留下任何跳動。

### 3.2 明文偏離票面的一點(誠實記錄)

票面寫「交叉核對日線價格同期是否有相應跳動(價格比例 × 股數比例 ≈ 1)」。
**這條檢測需要未調整拆股的原始價格,而倉內沒有原始價格**——
`daily_close.parquet` 是 `auto_adjust=true`(已調整拆股與股息),生產庫沒有價格表。
在已調整價格上,拆股完全不留痕跡,票面那條規則量不到東西。

倉內反而有**更強的工具**:上述拆股事件表,是事件本身而不是它的價格影子。
本票因此以事件表作為拆股的裁決依據,並用價格做一次反向核對——
確認每宗已知拆股在 `daily_close` 上**沒有**相應跳動(證明價格確實已調整)。
**這是工具替換,不是判準放寬:剔除拆股這條死線照守,而且守得比票面更嚴。**

### 3.3 單位刻度守衛(必要的資料完整性修補)

面板已知問題:同一家公司的 `diluted_shares` 在不同標籤/期別之間偶有**單位刻度**不一致
(例:代號 A 在 2009-10 是 345,000,000,在 2009-12 是 346——後者以百萬為單位申報)。
120,302 格之中約 1,069 格(0.9%)的量級明顯離群。不處理的話,一次刻度跳動會被算成
「股數收縮 99.9999%」,直接污染 D1。

規則(在 3.1 對齊之後施行,所以真拆股不會誤中):

1. 對每家公司,計 `log10(shares_adj)` 的**只用過去**擴張中位數(不含當月,
   嚴格 point-in-time,無前視)。
2. 過去觀測少於 3 個 → 不判,照留。
3. `|log10(當月) − 過去中位數| ≥ 1.0`(即差 10 倍以上)→ 判為刻度異常。
   對齊後真拆股已不留跳動,故 10 倍門檻不會誤殺公司行動。
4. 刻度異常者:若比率在 10 的整數次方(1e±3 / 1e±6 / 1e±9)的 ±25% 之內 →
   按該次方修復;否則 → **設為缺值**。
5. 修復數與缺值數入 meta。

### 3.4 疑似拆股剔除(票面死線,照做)

在 3.1–3.3 之後計 `r12 = shares_adj(t)/shares_adj(t−12m) − 1`。

- `|r12| ≥ 40%` → 標記為**疑似拆股**。
- 交叉核對:該 12 個月窗口內拆股事件表有無事件。
  - **有** → 確認拆股(即 3.1 的對齊漏了它),該窗口 shrink **設為缺值**。
  - **無** → 判為真實的大額回購 / 大額發行 / 併購換股,**保留**,
    但逐筆列入 `out/flagged_big_moves.csv`,並另做一次把全部 `|r12| ≥ 40%` 剔清的
    敏感度跑數(只作附註,不改主判詞)。
- 剔除數、修復數、保留數與名單全部入 `out/meta.json`。

## 四、量度

### 4.1 排名相關度

每月 m:在合資格池上算 shrink 與**下一月回報**的 Spearman 秩相關。
報全期**中位數**與 **Newey-West t**(lag = 6,固定,不得事後調)。
t 檢定的對象是月度相關度序列的平均值。

### 4.2 十分位

每月底按 shrink 由大到小分十等分:**D1 = 收縮最多,D10 = 膨脹最多**。
- 等權,**月換倉**;訊號在月底收市讀,**下一個交易日收市**執行(不得同日)。
- 兩隻組合:**D1 多 / D10 空**(長短各半、合計曝險 1.0);**只做多 D1**(等權滿倉)。
- 成本:每邊 **15bp** 為主口徑,另報 **0 / 25 / 50bp**。
- 持倉之間權重隨價格漂移;持倉中途斷價則當日收市強制離場、權重平攤給生還者、照收成本。

### 4.3 四條基準

1. **SPY**(含息,`auto_adjust` 已含股息)
2. **XLK**
3. **同池等權**(該月全部合資格名單等權、同樣月換倉)
4. **運氣帶**:每月在同池隨機抽**與 D1 同樣隻數**、同樣月換倉,2,000 條路徑,
   報第 5 至第 95 百分位。四個成本水平齊。

全部基準與臂用同一段日期、同一條執行規則。

### 4.4 控制規模與盈利能力

- 規模 = `shares_adj × 月底收市價`(兩邊基準已對齊,見三)。
- 盈利能力 = `cfo_ttm ÷ assets`(面板 PIT)。
- **路線甲(雙重排序)**:先分 5 個規模五分位,每組之內再分 5 個 shrink 五分位;
  shrink 利差 = 五個規模組的(Q1−Q5)月度回報差之平均。盈利能力同法。
  **保留幅度 = 控制後利差 ÷ 未控制的 Q1−Q5 利差**(同為五分位,可比)。
- **路線乙(Fama-MacBeth)**:每月橫截面回歸
  `ret(m+1) ~ shrink_rank + size_rank + profit_rank`(三者皆化為 [0,1] 的百分位秩)。
  **保留幅度 = 多元回歸的 shrink 係數 ÷ 單變量回歸的 shrink 係數**。
- 兩條路線都報;判準取**兩者中較低**那一個。

## 五、判準(存在 / 不存在 / 量不出)

照長名單 S3 原文:

- **存在** = 排名相關度中位 **≥ 0.015** 且 Newey-West **t ≥ 2.5**,
  **而且**控制規模與盈利能力後保留 **≥ 50%**。
- **不存在** = 排名相關度中位 **≤ 0.005**,**或**控制後保留**不足 30%**(判為化身)。
- 其餘一切情況 = **量不出**。
- 兩段(2010–2016 / 2017–2026)的方向另報,**不參與判詞**,只作衰減線索。
- 判詞以 A 版為主。B 版另出一個判詞,不合則在報告寫明兩版分歧。

# 訂正一(2026-09-02,在接觸任何回報數字**之前**)

**上面第三節第 3.3 條原文一字未改,但已作廢,由本節取代。原因記在下面。**

## 為什麼要訂正

原 3.3 條用「該公司過去觀測的擴張中位數」作刻度錨。試跑資料準備步(**未跑任何回報**)
發現這條規則會反過來把好資料改壞:

若一家公司**最早那幾個月**的申報就是錯刻度(例如 LIN 開頭幾格以千為單位、
COP 開頭一百格以千為單位),擴張中位數本身就被毒化,之後整條正確的序列反而
全部被判為「偏離錨十倍」——A 版因此被「修復」了 5,705 格(佔 4.7%),
方向是把對的改成錯的。這是規則本身的缺陷,不是資料的問題。

**訂正時本票尚未計算任何回報、任何相關度、任何組合成績**,所以這次改動
不可能是照著結果調參。凍結的用意(不准對著成績改規則)完整保住。

## 3.3′ 單位刻度守衛(取代 3.3)

實例(全部由資料本身驗出,非猜測):MCD 有 31 格是 `732.3`(以百萬為單位)、
COP 有 100 格是 `1495700`(以千為單位)、GRMN 有 54 格是 `196457`(以千為單位)、
AMG 有 7 格是 `4.76e10`(大三個量級)、FTI 有 4 格是 `1.0`(純垃圾)。

在 3.1 拆股對齊**之後**施行,逐家公司:

1. **錨** = 該公司全樣本 `log10(shares_adj)` 的中位數。
   這是一個**量級常數**,不是回報資訊;它只用來「丟棄」或「換算單位」,
   保留下來的數值一個都不會被它改動方向。誠實聲明:此錨用了全樣本,
   嚴格而言不是 point-in-time;採用它的理由是上一段那個毒化問題,
   而它能夠影響結果的唯一途徑是「哪幾格被丟」,與該格之後的回報無關。
2. `dev = log10(值) − 錨`。`|dev| < 0.7`(五倍以內)→ 不動。
3. `|dev| ≥ 0.7` 而原值 **< 100** → 判為垃圾,設缺值(FTI 的 `1.0`)。
4. `|dev| ≥ 1.5`(逾三十倍)且 `dev` 落在某個非零整數 `k` 的 **±0.35** 之內
   → 判為單位刻度錯,除以 `10^k` 修復。
   **1.5 的下限是為了保護真實的公司行動**:KDP 2018 年併購令股數由 1.8 億跳到
   13.7 億(`dev` = 0.88),落在 1.5 之下,一格都不會被動到。
5. 修復之後(或未修復),數值不在 `[1e5, 1e11]` 之內 → 設缺值。
6. `0.7 ≤ |dev| < 1.5` 而未觸發上述任何一條 → **保留**,當作真實的大額股數變動,
   交給 3.4 的四成門檻去處理。
7. 該公司非缺值觀測少於 6 個 → 不判,全部照留。

修復數與缺值數入 `out/meta.json`。實測:A 版修復 1,022 格、設缺值 87 格
(對照原 3.3 的 5,705 / 1,095)。

**本節以外,其餘判準一字不改;第四、五節(量度與判詞)完全未動。**
