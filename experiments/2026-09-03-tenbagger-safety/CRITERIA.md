## 零、本票答什麼

用戶 2026-09-03 十條原則第八條要的是「下行風險有限、潛在上行空間卻非常大的不對稱機會」。
KARST-160(D-145)量到十倍股起步時**細、燒錢、營業額增速分不開、在發新股**,表面上與
「下行有限」矛盾。本票問的是一個比品質過濾器窄的問題:

> **資產負債表式的安全邊際(公司死不了)會不會像品質過濾器一樣誤殺十倍股?**

方向不預設。三個可能的答案本票都接受:
安全邊際與十倍**同向**(安全的公司更易十倍)、**反向**(安全邊際過濾器誤殺十倍股)、
或者**分不開**(這個維度上兩者無分別,即安全邊際過濾器是「免費」的)。

## 二、面板 v2 缺的欄怎樣補

面板 v2 有 `cash`、`lt_debt`、`assets`、`liabilities`、`equity`、`cfo_ttm`、`capex_ttm`。
**沒有**短期債務、商譽、無形資產三樣。本票**不新抓任何東西**:
`experiments/2026-09-02-fundamentals-panel/data/secfacts/` 已有 698 份 EDGAR companyfacts
快取(KARST-146 抓的),**只讀**,由它補三欄,規則與面板一模一樣
(直接 import `build_panel.py` 的 `first_versions` / `pick_tag` / `period_type`,不自寫一套)。

| 新欄 | 標籤(按優先次序) | 類型 |
|---|---|---|
| `st_debt` | ShortTermBorrowings / LongTermDebtCurrent / OtherShortTermBorrowings / CurrentPortionOfLongtermBorrowings(ifrs) / ShorttermBorrowings(ifrs) | 存量,四個標籤**相加**見下 |
| `goodwill` | Goodwill | 存量 |
| `intangibles` | IntangibleAssetsNetExcludingGoodwill / FiniteLivedIntangibleAssetsNet / IntangibleAssetsOtherThanGoodwill(ifrs) | 存量 |

`st_debt` 特別處理:短期借款與「一年內到期的長期債務」是**兩件不同的東西**,同一家公司
可以同時有,所以不可以「取優先次序第一個有數的」。做法:分別取 `ShortTermBorrowings` 系
與 `LongTermDebtCurrent` 系兩條序列(各自照知情時點規則),然後**相加**;只有一條有數就
只計那一條;兩條都無數 → `st_debt` 缺值。

## 三、三個安全邊際特徵(t0 取值)

| 代號 | 名 | 算法 |
|---|---|---|
| **S1** | 淨現金對市值 | `(cash − total_debt) ÷ mcap`,`total_debt = lt_debt + st_debt` |
| **S2** | 現金跑道(年) | `cash ÷ burn`,`burn = max(0, −(cfo_ttm − capex_ttm))` |
| **S3** | 有形資產淨值對市值 | `(equity − goodwill − intangibles) ÷ mcap` |

缺值處理(寫死,不准跑數之後放寬):

- **S1**:`lt_debt` 缺 → S1 缺值。`st_debt` 缺 → **當 0**(公司沒有貼這個標籤,多數是真的
  沒有短期借款;當 0 會令淨現金偏樂觀,方向對兩組一致,報告要報 `st_debt` 覆蓋率)。
  `cash` 或 `mcap` 缺 → S1 缺值。
- **S2**:`cfo_ttm` 或 `capex_ttm` 缺 → S2 缺值。`burn = 0`(自由現金流 ≥ 0)→ **記為無限**,
  排序時取封頂值 **99 年**;有限值一律封頂 99(即 ≥99 年與無限並列同分)。`cash` 缺 → 缺值。
- **S3**:`equity` 或 `mcap` 缺 → S3 缺值。`goodwill` / `intangibles` 缺 → **當 0**
  (companyfacts 沒有這個標籤,多數是公司沒有商譽/無形資產);兩者的覆蓋率要報。

兩條穩健性對照(同時報,不取代主口徑):

- **S2b**:`burn = max(0, −cfo_ttm)`(只看經營現金流,不扣資本開支)。
- **S3b**:`equity ÷ mcap`(不扣商譽與無形資產,即帳面淨值對市值)。

## 四、分辨力:逐年加權 AUC

秩 AUC,算法直接沿用 KARST-160 `features_t0.py` 的 `auc()`:x 為特徵值、y 為 `is10x`,
缺值剔除。**0.5 = 完全分不開;高於 0.5 = 數值大的一邊才是十倍股;低於 0.5 = 數值細的一邊
才是十倍股。**

- **全樣本 AUC**:全部可算格一次過算。
- **逐年加權 AUC**:按 t0 年份分層,某年**十倍格 ≥ 5** 且兩類都有格才入數,各年 AUC 以該年
  格數加權平均。(這一條防「十倍股集中在某幾年」造出來的假分辨力。)

**判詞規則(先寫死):**

| 情況 | 判詞 |
|---|---|
| 可算格 ≥ 1,000 **且** 可算十倍格 ≥ 50 **且** \|逐年加權 AUC − 0.5\| ≥ **0.05** **且** 全樣本與逐年加權兩個 AUC 同在 0.5 的同一側 | **存在**(附方向) |
| 可算格 ≥ 1,000 且 可算十倍格 ≥ 50 但 \|逐年加權 AUC − 0.5\| < 0.05 | **不存在** |
| 可算格 < 1,000 或 可算十倍格 < 50,或兩個 AUC 分處 0.5 兩側 | **量不出** |

0.05 這個數不是統計檢定,是一條事先講定的實用線:KARST-160 最強的一項(起點市值)
偏離 0.282,最弱的一項(營業額增速)偏離 0.082。0.05 以下的東西,拿來做過濾器沒有意義。

## 五、誤殺率 vs 剔走率(三個門檻)

安全邊際過濾器 = **只准通過有安全邊際的格,其餘剔走**。

| 門檻 | 定義 |
|---|---|
| **T1** 淨現金為正 | `S1 > 0` |
| **T2** 跑道 ≥ 2 年 | `S2 ≥ 2`(無限計為通過) |
| **T3** 有形淨值 ≥ 市值三成 | `S3 ≥ 0.30` |
| **T-嚴格** | 三條所需欄位**全部算得出**,且三條**全部**成立 |
| **T-實務** | 算得出的每一條都成立(至少要算得出一條);算不出的那條不當作不通過 |

每個門檻報:

- **誤殺率** = 被剔走的十倍格 ÷ 有齊該門檻所需欄位的十倍格;
- **剔走率** = 被剔走的全部格 ÷ 有齊該門檻所需欄位的全部格;
- **比值** = 誤殺率 ÷ 剔走率。**比值 > 1** = 這個過濾器剔十倍格剔得比一般格狠(即誤殺);
  **比值 ≈ 1** = 它對十倍格與一般格一視同仁(即這個過濾器在十倍這件事上是「免費」的);
  **比值 < 1** = 十倍格比一般格更容易通過。
- 覆蓋:有齊欄位的格數與十倍格數。

**這些不是成績。** 門檻(0、2 年、三成)是常識線,不是由這批數據調出來的,亦沒有在這批
數據上掃過參數;但它們亦沒有在倉外的新窗上驗過。報告只作描述。

## 六、死亡率:同一批「細而爛」公司之中,誰歸零

群體(先框死):`mcap < 25 億美元`(KARST-160 量到的十倍股起步中位市值)**且**
`in_index == 0`(起點時不在標普 500 之內)的格。

**死亡**(t0 之後五年窗之內,任何一條成立即算):

- (a) 窗內最低收市價 ÷ t0 收市價 − 1 ≤ **−90%**;
- (b) **退市**:該代號的價格序列最後一個有價日 < `t0 + 5 年`,且該最後有價日
  < 價格面板最後一個交易日 − 90 日(用來分開「真的斷了」與「面板尾端本來就到此為止」)。

分兩組報:**有安全邊際**(T-實務通過)/ **無安全邊際**,各報格數、死亡格數、死亡率,
以及兩組之差(百分點)。同時報這兩組各自的十倍率作對照——**這一格才是本票的核心對照:
安全邊際同時買到幾多「不死」與賣掉幾多「十倍」。**

**誠實限制(必須寫入報告)**:本宇宙 728 家全部是活到今日的公司,真正退市的那一批大部分
根本不在宇宙內,所以死亡率必然**系統性偏低**;(b) 退市那一條只捉得到宇宙之內中途斷價的
少數。兩組之間的**差**比水平值可信,但差本身也被同一個偏差壓縮。

## 七、市值分組內對照(確保不是規模效應的重述)

按每個 t0 年份之內 `log_mcap` 的**三分位**分組(細 / 中 / 大),組內重報:
三個特徵的全樣本 AUC、T1/T2/T3 的誤殺率與剔走率。
**看的是方向會不會翻。** 若某特徵的方向在三組之內一致,結論不是規模效應的重述;
若方向在細股組消失,則本票的結論只是 KARST-160 「愈細愈易十倍」的另一種寫法,報告要照講。

同時在**同一批可算格**上重算 KARST-160 的三項對照臂(`log_mcap`、`in_index`、
`shares_chg_12m`)的 AUC,確保新舊兩票的數字在同一個樣本上可比。
