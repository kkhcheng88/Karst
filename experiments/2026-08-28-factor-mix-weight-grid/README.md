# 因子混合策略:四隻因子 ETF 的權重掃描(KARST-029 首個實跑)

用戶 2026-08-28 明令首個掃描對象是因子混合策略的權重矩陣,原話:

> I think 因子混合策略 is not just 25% each ... with matrix-like of running, I would like to
> know what is the best driver to move between 4 to get the best portfolio just with the 4 ...
> I don't mind overfitting at first

這個目錄是那次掃描的產物。**只交表與判讀,不裁定哪一組權重該用**——那是用戶的
領域(D-008)。掃出來的最優**不是現役設定**:本目錄一句 `set_active_setup` 都沒有。

## 掃的是什麼

| 項目 | 內容 |
|---|---|
| 策略 | 因子混合(ETF 版)第 1 版 |
| 持倉 | QUAL(質素)、VLUE(價值)、MTUM(動能)、USMV(低波)四隻因子 ETF |
| 基準 | SPY 與 QQQ(同一個快照裡,但**一股不持**,只做對照尺) |
| 期間 | 2015-01-02 ~ 2026-08-26,2,929 個交易日 |
| 數據快照 | `2026-08-28-000b4820a23a`(舊 `2026-08-27-91a5d51339d9`,見下「數據目錄重建」) |
| 引擎 | vectorbt 0.1.0 |
| 掃描格 | 四個權重的**單純形格**(加總必為一)× 換倉節奏(月度、季度) |
| 主軸指標 | 對 SPY 的年化超額;另一份報告以最大回撤為主軸 |

**相鄰的定義**(判平原與孤峰全靠它):單純形格上「相鄰」= **把一步的權重由其中
一格移去另一格**(一個 +一步、一個 −一步,其餘不動),所以四個權重的內部格最多
十二個鄰居、角落格只有三個。節奏那一維再各自移一步或不動。這條定義印在每一份
報告的頂頭,不用翻碼也讀得到。

## 兩輪

| 輪次 | 步長 | 格數 | 目錄 |
|---|---|---|---|
| 粗掃 | 10% | 286 × 2 節奏 = **572 格** | [`results-10pct/`](results-10pct/) |
| 細掃 | 5% | 1,771 × 2 節奏 = **3,542 格** | [`results-5pct/`](results-5pct/) |

10% 的格是 5% 的格的**子集**,所以細掃時粗掃那 572 格一格都沒有重跑——直接讀回
已有的運行(每格一個運行編號,同一格重掃不重跑)。

⚠ **10% 步長排不出「各 25%」**:十步分不均四格。所以固定四等分那一格在粗掃裡是
**對照格**另外跑的(照樣落痕、照樣有運行編號),而 5% 的格本身就含住它。

## 重跑

倉根目錄:

```
set PYTHONUTF8=1
python experiments/2026-08-28-factor-mix-weight-grid/run_sweep.py --step 0.10 --min-trades 30 --margin 0.005 --quantile 0.90
python experiments/2026-08-28-factor-mix-weight-grid/run_sweep.py --step 0.05 --min-trades 30 --margin 0.005 --quantile 0.90
```

三個門檻沒有預設值可言(寫在命令列,印在報告裡):`--min-trades` 成交少於這個數
判無效、`--margin` 高出鄰域平均幾多才算孤峰、`--quantile` 平原高地由哪一個分位起計。

重跑一次不會重算:每一格的運行編號由「策略版本 × 參數集 × 期間 × 數據快照 ×
引擎版本」算出來,庫裡已經有那個編號就直接讀回,一次引擎都不碰。要真正重算,
先換數據快照或者換引擎版本——那本來就是另一次運行。

數據快照與運行序列(`data/`)不入 git;快照要重抓的話見 `karst.data` 的管線。

[`../2026-08-28-rebuild/成績新舊對照.md`](../2026-08-28-rebuild/成績新舊對照.md)。
