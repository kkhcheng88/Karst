# KARST-058:VIX 與 VIX_3M 換來源的兩來源對照

> 一句講完:**免費轉發那一層自 2026-07-17 停更,指數本身沒有停。**
> 改由 Cboe 官方免費歷史檔直取之後,VIX 三個月指數由 2026-07-18 起每個交易日
> 都有數,期限結構開關自此每日都判得出;兩個來源在重疊的十一年半裡,
> 2,931 日之中只有 **3 日**的讀數差過 0.001 點。

跑法(倉根目錄):

```
set PYTHONUTF8=1
python experiments/2026-08-29-vix3m-source/compare_sources.py
```

## 一、要答的是什麼

換來源的風險不在「新來源有沒有數」——那看一眼就知。風險在**新來源的數與舊來源
對不上,而我們照舊拿換之前的成績與換之後的成績比**:兩批成績看上去同一個口徑,
其實底下已經是兩條不同的數。所以這裡逐日逐格對,把差異攤出來,不做平均掩蓋。

| 項目 | 舊 | 新 |
|---|---|---|
| 來源 | yfinance(免費轉發) | Cboe 官方免費歷史檔 |
| 來源代號 | `^VIX` / `^VIX3M` | `VIX` / `VIX3M` |
| 取數方式 | `yfinance.download` | `cdn.cboe.com/.../<代號>_History.csv` |
| 鑰匙 / 配額 | 無 | 無 |
| 新增套件 | — | 無(只用標準庫 `urllib`) |
| **序列代號** | `VIX` / `VIX_3M` | **一個字都沒有改** |

序列代號不變是這次改動的整個重點:驅動器、快照結構、報告全部不用動,改的只是
名冊上那兩格。名冊連同快照一併凍結,所以「這條讀數當日由哪個來源取」在已凍結的
快照裡查得回(`registry.parquet` 新增 `source` 一欄)。

## 二、重疊期差異(窗口 2015-01-02 ~ 2026-08-27)

| 序列 | 重疊日數 | 差 > 0.001 的日數 | 平均絕對差 | 最大絕對差 | 舊來源尾日 | 新來源尾日 |
|---|---|---|---|---|---|---|
| `VIX` | 2,931 | 3 | 0.00094 | 2.61(2026-02-06) | 2026-08-27 | 2026-08-27 |
| `VIX_3M` | 2,901 | 3 | 0.00009 | 0.15(2021-08-11) | **2026-07-17** | **2026-08-27** |

其餘每一日的差全部在 1e-6 以下——那不是數據分歧,是 yfinance 用 32 位浮點回數
造成的表示誤差(例:`17.239999771118164` 對 `17.24`)。歸一化取 7 位有效數字之後,
這一級的差**連進不進得到快照都分不出來**。

差得出來的只有六格(五個日子),逐格列明:

| 日期 | 序列 | 舊(yfinance) | 新(Cboe) | 取值理由 |
|---|---|---|---|---|
| 2026-02-06 | `VIX` | 20.37 | **17.76** | 見下節,舊來源那一格是錯印 |
| 2021-08-11 | `VIX_3M` | 20.82 | **20.67** | 官方檔是這條指數的出處,轉發層的修訂未必跟得足 |
| 2021-08-11 | `VIX` | 16.17 | **16.06** | 同上 |
| 2021-10-01 | `VIX_3M` | 22.95 | **23.05** | 同上 |
| 2021-10-01 | `VIX` | 21.10 | **21.15** | 同上 |
| 2015-07-23 | `VIX_3M` | 14.92 | **14.93** | 同上 |

**取值一律取 Cboe。** 理由不是「新的比較好」,是**出處**:VIX 與 VIX3M 是 Cboe
自己編製、自己發布的指數,官方歷史檔就是這條數的正本;yfinance 是轉發。兩邊對不上
的時候,正本說了算——這與價格那條管線「以交易所收市價為準」是同一條道理。

## 三、2026-02-06 那一格:換來源順手修掉的一個假訊號

| 日期 | 舊 VIX | 舊 VIX_3M | 舊比率 | 新 VIX | 新 VIX_3M | 新比率 |
|---|---|---|---|---|---|---|
| 2026-02-05 | 21.77 | 22.45 | 0.970 | 21.77 | 22.45 | 0.970 |
| **2026-02-06** | **20.37** | **20.37** | **1.000** | **17.76** | 20.37 | **0.872** |
| 2026-02-09 | 17.36 | 20.09 | 0.864 | 17.36 | 20.09 | 0.864 |

舊來源在這一日把 VIX 印成 20.37——**與同日的 VIX_3M 一模一樣**,即那一格是把三個月
那條數複製了過去。後果不是「差 2.61 點」這麼簡單:期限結構 = VIX ÷ VIX_3M,兩個
數字相同即比率剛好 **1.000**,而 1.00 正是這個驅動器掃描格上的一個門檻值。
換句話說,舊那份數在那一日的比率**剛好坐在倒掛與否的分界線上**,而它坐在那裡的
唯一原因是一個複製錯誤。

期限結構整體沒有走樣:倒掛日數(比率 > 1)兩邊都是 220 日,比率平均 0.8901 對 0.8896。

## 四、尾段補回了什麼

`尾段補回-VIX_3M.csv`:2026-07-20 至 2026-08-27 共 **29 個交易日**的 VIX_3M 讀數,
舊來源一日都沒有。

落到宏觀快照裡(快照窗口對齊價格快照那條主日曆,尾日 2026-08-26)就是:

| | 舊快照 `2026-08-28-810facb50382` | 新快照 `2026-08-28-dc2d9f1a1778` |
|---|---|---|
| `VIX_3M` 真有讀數 | 2,901 日 | **2,929 日** |
| `VIX_3M` 前值填補 | 3 日 | **0 日** |
| `VIX_3M` 留空 | 25 日 | **0 日** |
| 最後一個讀數 | 2026-07-17 | **2026-08-26** |

留空的 25 日加填補的 3 日 = **28 個交易日**,期限結構驅動器在這段日子裡每日都判
「數據不足」退回熱身期權重。補回之後,這個開關由 2015-01-02 起至窗口尾**每一個
交易日都有訊號**。

## 五、驅動器重跑一次示例

`vix_term-rerun/`:用新宏觀快照把 VIX 期限結構驅動器那 30 格重跑一次(零成本口徑,
D-030)。**只跑這一個驅動器**,不重跑六個驅動器那 180 格。

| | 舊快照 | 新快照 |
|---|---|---|
| 最優格 | `threshold=1.05、tilt=1、cadence=monthly` | **同一格** |
| 對 SPY 年化超額 | +0.6409% | +0.5879% |
| 成交筆數 | 74 | 70 |
| 判讀分佈 | 山脊 1、孤峰 1、普通 28 | **一樣** |

換來源沒有改變這個驅動器的形狀,亦沒有改變它的結論——它照舊贏不過價格驅動器
(相對強弱 +4.49%、因子動量 +3.57%)。差的那 5.3 個基點來自尾段那 28 日加上
2026-02-06 那一格。**這裡不裁定哪個驅動器該用**(D-008),只交表。
