# 因子輪動:四個驅動器的矩陣掃描(KARST-036)

用戶 2026-08-28 原話:

> I would like to know what is the best driver to move between 4 to get the best portfolio just
> with the 4 ... I don't mind overfitting at first

KARST-029 那次答的是「四格權重**固定**時哪一組最好」。這一次答的是下一個問題:
**權重不再固定,靠什麼訊號推動它在四隻之間移,最有效?**

這個目錄是那次掃描的產物。**只交表與判讀,不裁定哪一個驅動器該用**——那是用戶的
領域(D-008)。掃出來的最優**不是現役設定**:本目錄一句 `set_active_setup` 都沒有。

## 掃的是什麼

期間、快照、基準、熱身期四樣**四個驅動器完全一樣**,所以格與格之間的差異只可能
來自驅動器與它的參數。

## 四個驅動器

驅動器(rotation driver)是策略層的可換件,四個走同一個接口:**收四隻 ETF 截至
決策日收工為止的收價,回四格權重**。換驅動器不改引擎、不改因子混合策略的目標比重
路徑——策略層照樣只砌一張「日期 × 實體編號 → 目標比重」的表交出去。

| 驅動器 | 訊號 | 掃描的參數 | 格數 |
|---|---|---|---|
| 因子動量排名 | 過去 L 個月報酬排名 | L = 1/3/6/9/12 月;`winner`(全押第一)或 `rank`(名次遞減 4:3:2:1) | 5 × 2 × 2 節奏 = **20** |
| 相對強弱對 SPY | 過去 L 個月報酬 vs SPY | L = 1/3/6/9/12 月;全輸時 `cash`(持現金)或 `equal`(等權) | 5 × 2 × 2 節奏 = **20** |
| 逆波幅 | 過去 L 日每日波幅的倒數 | L = 21/63/126/252 日;集中程度 1 或 2 次方 | 4 × 2 × 2 節奏 = **16** |
| 大市趨勢開關 | SPY 收價 vs M 日均線 | M = 50/100/150/200 日;押注比重 50% / 75% / 100% | 4 × 3 × 2 節奏 = **24** |

換倉節奏(月度、季度)四個驅動器都掃,合共 **80 格**,每格一個運行編號。

**相鄰的定義**(判平原與孤峰全靠它):笛卡兒積格上「相鄰」= 每個軸最多移一步、
且不可全部不動;無序的軸(`mode`、`fallback`——`winner` 與 `rank` 不是一步之遙)
同軸任何兩個取值皆相鄰。這條定義印在每一份報告的頂頭。

## 判讀:兩個贏家都是孤峰

| 驅動器 | 平原 | 孤峰 | 無效 | 最優格的鄰域平均 |
|---|---|---|---|---|
| 因子動量排名 | 0 | 2 | 0 | −0.17%(本格 +3.24%,落差 3.41pp) |
| 相對強弱對 SPY | 0 | 1 | 0 | +1.28%(本格 +4.04%,落差 2.76pp) |
| 逆波幅 | 0 | 0 | 0 | −1.23%(本格 −0.85%) |
| 大市趨勢開關 | 0 | 2 | 0 | −1.85%(本格 −1.06%) |

按 D-016 第 3 條與 KARST-029 的判準,**兩個跑贏固定權重的驅動器,它們的最優格都判
孤峰**——峰值明顯高於四周,即那個數字有很大機會是擬合噪音而不是那組參數本身有效。
兩件事要一齊看:

- **因子動量排名**的最優格(L=3、全押第一、月度)四周塌得最狠:鄰域平均 −0.17%,
  即改一改回望期或者換個分注法,超額就沒有了。但它的優勢**分佈在三段之中的兩段**
  (2020–2022 與 2023–2026 都贏固定權重),不是靠單一個時期。
- **相對強弱對 SPY** 的最優格是四個驅動器之中唯一「單點最優」與「鄰域平均最高」
  **同一格**的,鄰域平均 +1.28% 亦是四個之中最高;它的最大回撤 −21.1% 比所有對照
  淺十三個百分點,Sortino 1.24 也是全場最高。但它的超額幾乎全部來自 **2020–2022 那
  一段(+12.47%)**——那正是它按參數走去持現金的那一段。換句話說,它贏的是一次
  股災,不是十一年。

**一個平原都沒有,要打個折來讀。** 平原的判準是「本格與鄰域平均雙雙排前一成」,
而這四個格只有 16 至 24 格(KARST-029 那次是 3,542 格),前一成即頭兩格,鄰域平均
要同時擠進頭兩格幾乎不可能。所以「0 平原」在這裡**不等於**四個驅動器全部不穩健,
它更多是格太細的後果。要判得準,下一步是把格加密(例如 L 逐月掃)。

## 外部數據

**一個都沒有用。** 四個驅動器的訊號全部由快照裡六隻 ETF 自身的收價算出來——沒有
VIX、沒有債息、沒有任何第三方序列,所以沒有來源要列、沒有費用要問、亦沒有知情
時間以外的處置要交代。這一點寫死在 `karst.strategies.factor_rotation.EXTERNAL_DATA`
(現時是空的),日後有驅動器非要外部序列不可,要先在那裡列明「來源、免費與否、
知情時間怎樣處置」才准實作,驗收測試盯住這一格。

知情時間本身照 D-021 第 3 條辦:驅動器收到的價格歷史由 `closes.loc[:決策日]` 切出來
——**最後一行就是決策日那一根**,之後的價格它連拿都拿不到;成交一律在下一根 K 線
的開價。這一條有專門的測試盯住(`tests/test_factor_rotation.py`)。

## 重跑

倉根目錄:

```
set PYTHONUTF8=1
python experiments/2026-08-28-factor-rotation-drivers/run_rotation_sweep.py
```

三個判讀門檻沒有預設值可言(寫在命令列,印在報告裡):`--min-trades` 成交少於這個
數判無效(用 30)、`--margin` 高出鄰域平均幾多才算孤峰(用 0.005)、`--quantile`
平原高地由哪一個分位起計(用 0.90)。`--warmup` 是熱身期根數(用 252),
`--drivers` 可以只跑其中幾個。

重跑一次不會重算:每一格的運行編號由「策略版本 × 參數集 × 期間 × 數據快照 × 引擎
版本」算出來,庫裡已經有那個編號就直接讀回。四個固定權重對照正是這樣來的——它們
是 KARST-029 已經跑過的運行,這次一格都沒有重跑。

數據快照與運行序列(`data/`)不入 git。

## 能力本體在哪

| 檔 | 內容 |
|---|---|
| `karst/strategies/factor_rotation.py` | 驅動器接口、四個驅動器、目標比重路徑、跑一次回測 |
| `karst/sweep/factor_rotation.py` | 掃描接法:參數格、一格怎樣跑、成績表、分段超額 |
| `tests/test_factor_rotation.py` | 四條驗收條件各一個測試(離線合成價格) |

掃描四層(格 / 逐格跑 / 判讀 / 報告)本身住在 `karst/sweep/`,本票一個字都沒有改
它——因子輪動只是接上去的第二套策略,證明那四層真的與策略無關。
